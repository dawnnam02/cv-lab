# Plane 작업(WorkItem) 작성 양식

이 저장소의 **실행계획**과 **작업별 청사진**은 모두 이 양식을 따릅니다.
그래서 나중에 Plane에 옮길 때 내용을 그대로 붙여 넣으면 됩니다.

---

## 1. 작업종류

| 구분 | 코드 | 내용 |
|---|---|---|
| 운영 | `[HR]` | 인원 채용, 인터뷰 |
| 운영 | `[RES]` | 문제해결 연구, 부품 선정 |
| 운영 | `[DOC]` | 문서화 작업 |
| 제품 개발 | `[FW]` | 펌웨어 개발 |
| 제품 개발 | `[PCB]` | 회로설계, PCB 아트워크 |
| 제품 개발 | `[CAD]` | 기구설계 |
| 제품 개발 | `[QA]` | 제품 동작 검증, 시험 |
| 제품 생산 | `[MF]` | PCB 생산, PCBA, 하우징 생산, 제품 생산 |
| 제품 생산 | `[PROC]` | 부품 조달, 대체 부품, 외주 발주 업체 관리 |
| **신설 요청** | `[SW]` ⏳ | **분석·제어 소프트웨어 개발 (Python 분석 코드, 데이터 처리 파이프라인)** — *팀장 승인 대기* |

- 작업종류를 임의로 쓰거나 비워 두는 것은 **임시로만** 허용합니다.
  **1주일 안에 끝나지 않는 작업**은 위 표의 작업종류로 고쳐야 합니다.
- 표에 없는 작업종류가 필요하면 **팀장 승인**을 받아 추가합니다.
- `[SW]`가 승인되지 않으면 해당 작업은 `[RES]`로 바꿔 표기합니다.

### 이 과제에서 자주 쓰는 대응 예

| 이 과제의 작업 | 작업종류 |
|---|---|
| 부품 사양 계산, 부품 선정, 방법 조사 | `[RES]` |
| 부품 구매, 견적 | `[PROC]` |
| 측정대·지그·브래킷 설계 | `[CAD]` |
| 시편·지그 출력, 조립 | `[MF]` |
| 캘리브레이션 검증, 반복성·Gage R&R 시험 | `[QA]` |
| 카메라·스테이지 제어 코드 | `[FW]` 또는 `[SW]` |
| G코드 파서, 정합, 지표 계산 등 PC 분석 코드 | `[SW]` ⏳ |
| 절차서, 보고서, 논문 작성 | `[DOC]` |

## 2. 제목(Title)

```
[M모듈번호][C사이클번호W워크아이템번호][작업종류] 작업 이름
```

- 예: `[M1][C1W39][HR] 미도리 채용 인터뷰`
- 작업종류가 2개 이상이면 예외적으로 `/`로 구분할 수 있습니다: `[M1][C1W39][CAD/PCB] hub PCB 하우징 설계`
- 할 일이 2개 이상이면 workitem을 **나눠서** 작성합니다.
- 해당하는 모듈·사이클이 없으면 **임시로 0**을 씁니다.

> **이 저장소의 현재 상태**: 모듈·사이클 번호는 아직 정하지 않았습니다.
> 그래서 모든 작업을 `[M0][C0W번호]`로 쓰고, 대신 **Due Date를 반드시 적어 둡니다.**
> W번호는 저장소 전체에서 겹치지 않는 일련번호입니다.
> 번호가 정해지면 일괄 변경합니다.

## 3. 본문 항목

### 반드시 작성 (Must Write)

| 항목 | 내용 |
|---|---|
| **Objective** | 작업의 요약 설명과 **왜** 이 작업을 해야 하는지 |
| **Scope of Work** | 이 workitem에서 할 일을 **세분화해서 체크박스(`- [ ]`)** 로 작성 |
| **Completion Requirements** | 완료로 인정되기 위해 달성해야 할 조건 (가능하면 숫자로) |
| **Assignees** | 담당자 |

> 해당하는 cycle이 없는 workitem은 **Due Date를 반드시 명시**합니다.

### 작성 권장 (Recommended)

| 항목 | 내용 |
|---|---|
| **Sub-workitems** | Scope of Work가 많거나 범위가 크면 하위 workitem으로 나눔 |
| **Dependencies** | 먼저 끝나야 하는 workitem, 작업이 막히는 원인 |
| **Start / Due date** | 시작일, 마감일 |

---

## 4. 상태(Status)

| 상태 | 의미 |
|---|---|
| Backlog | 언젠간 해야 할 일 (기간이 정해지지 않음 / 해당 사이클이 아님) |
| ToDo | 해야 할 일 (기간이 정해짐) |
| InProgress | 작업 중 |
| Done | 작업 완료 |
| Cancelled | 작업 취소 (**팀장만** 변경 가능) |

그 외 상태는 Assignees가 직접 바꿉니다.

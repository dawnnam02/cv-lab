## 1. 목적

세 가지를 만듭니다.

1. **저장소 골격 (J1).** `src/cvlab/` 패키지, `pyproject.toml`, `requirements.txt`, `.gitignore`, 폴더 표시 파일. T15 · T4a가 바로 `import cvlab.judge`, `import cvlab.gcode`를 쓸 수 있게 합니다.
2. **설정·재현성 (J2).** `config/` 읽기, 시드 고정, 실행 기록 (`manifest.json`).
3. **명세 검증기 (F3 구현).** `docs/하드웨어-데이터-명세.md`의 필드표를 기계가 읽는 표로 뽑고, 가상·실측 데이터 폴더가 그 명세를 지켰는지 검사합니다. 일부러 망가뜨린 고장 표본을 **100 %** 잡아야 합니다 (청사진 §4.3 T6).

T3 시뮬레이터의 첫 통과 조건 (C3 "명세 검증기 100 %")이 이 검증기입니다. 검증기가 느슨하면 C3가 의미를 잃습니다.

- 하위 폴더에 `__init__.py`·`conftest.py`를 두지 않습니다. pytest 기본 import 방식에서 파일 이름이 겹치면 오류가 나므로 **시험 파일과 도우미 파일 이름 앞에 폴더 이름을 붙입니다** (`test_infra_*.py`, `infra_*.py`).

**공통 파일이 아직 없을 때:** T15 · T4a는 `PYTHONPATH=src`로 시험합니다. `src/cvlab/__init__.py`가 없어도 Python 3은 `cvlab`을 이름공간 패키지로 읽으므로 막히지 않습니다. 그래서 T6의 SV1이 늦어도 두 작업은 기다리지 않습니다. 반대로 T6는 `__init__.py`에 하위 패키지 import를 넣지 않습니다 (넣으면 두 작업의 미완성 코드가 서로를 깨뜨림).

## 6. 설계 규칙

### 6.1 스키마 추출 (`fields_v1.0.csv`)

| 열 | 뜻 | 뽑는 법 |
|---|---|---|
| `field` · `group` · `meaning` · `unit` · `dtype` · `req` · `example` · `rule_text` | 명세 필드표 7칸 원문 (+ 묶음) | `^\| \`(frame\|pos\|cal\|ref\|meta\|blt\|rep\|truth)\.[a-z0-9_]+\` \|` 행. 칸 수 7이 아니면 추출 실패 |
| `regex` | "정규식 \`…\`" 안의 식 | 여러 개면 `\|\|`로 잇고 하나라도 맞으면 통과 |
| `enum` | "값 ∈ {…}" 안의 값 목록 | 쉼표로 나눔. 대기 표시 `[대기: T14]`가 붙으면 그 규칙은 WARN |
| `min` · `min_op` · `max` · `max_op` | "a ≤ x ≤ b", "0 < x", "abs(x) ≤ c", "= v" | 다른 필드를 가리키는 범위 (`x ≤ \`meta.nozzle_dia_mm\``)는 여기 넣지 않고 CROSS 규칙으로 |
| `file` | 그 묶음 파일 이름 (§0.2) | 묶음별 표 |
| `excluded` · `excluded_reason` | 검사에서 뺀 묶음이면 `true`와 사유. 지금 blt 26필드가 `true`, 사유 "D-14 BLTouch 교차검증 제외 (팀장 지시 2026-10-27, 명세 개정 전)" | 명세 표기가 생기면 사유를 명세 절로 (SV13) |

- 자동 변환 못 한 "검증 규칙" 칸은 규칙표에 손 규칙 (CROSS · FILE)이나 보류로 반드시 연결합니다. 미분류 0이 SV5 조건입니다.
- 명세 지문 (SHA-256)이 `SOURCE.txt`와 다르면 `test_infra_schema_sync`가 실패합니다. 실패하면 다시 뽑고, 규칙표 차이를 대조표에 적습니다.

### 6.2 규칙 종류와 심각도

| 종류 | 예 | 심각도 |
|---|---|---|
| REQ | 필수 칸이 빔. 조건부는 조건이 참일 때만 | ERROR |
| DTYPE | int에 `1.5`, int64에 `1e9`, bool에 `True`·`1`, float에 `NaN`, list·dict 자리에 다른 JSON 형 | ERROR |
| REGEX · ENUM · RANGE | 명세 칸 그대로 | ERROR (명세가 "경고"라고 쓴 규칙만 WARN) |
| CSV | UTF-8 BOM, 머리글 순서 ≠ 필드표 순서, 모르는 열, 결측을 `NaN`·`nan`·`null`로 씀, 줄 끝 `\r\n` | ERROR |
| JSON | 모르는 키, 접두어가 붙은 키 (`meta.scan_id`) | ERROR |
| JSON 형식 (§0.5, S-2) | JSON-06 들여쓰기 2칸, JSON-07 `ensure_ascii=False` (한글을 유니코드 이스케이프로 바꾸지 않음). "길이 mm는 소수 4자리 이상"은 표기 규칙인지 정밀도 규칙인지 명세에 없어 보류 H-FMT-01 (T1에 넘김) | WARN |
| CROSS | 같은 스캔 안 scan_id 일치, `meta.n_frames` = 프레임 행 수, `meta.wait_after_layer_s` 식, `meta.z_offset_mm` 세션 안 같음, `meta.bed_ref_id` → `ref.kind = bed_bare`, `post` 짝 (`meta.paired_scan_id`), timing ⇔ thermal_state, `meta.tolerance_mm = 0.20`, 캠페인 V ⇔ virtual 등 명세 칸의 관계 | ERROR (명세가 경고면 WARN) |
| FILE | §8 폴더 트리, 이름 정규식, 고정 파일 이름, 시편·반복마다 `post/` 정확히 1개, 프레임 파일 존재, `frame.sha256` · `meta.files_sha256` 재계산 일치, 경로에서 뽑은 세션·시편·반복·층 = meta 값 | ERROR |
| LEAK | `data/raw` 아래에 `truth.` 키·`truth_` 열·`truth.json`·`_truth` 폴더 (청사진 §5.2, 명세 §0.1) | ERROR |
| 보류 | 데이터만으로 못 정하는 것 ("식었다" 기준 T15, "[대기: T14]" 허용 값, 실측에서만 쓰는 경고) | 검사 안 함, 사유 필수 |

- 탐지율은 ERROR 규칙으로 셉니다. WARN 규칙은 "경고가 실제로 나오는지"를 따로 시험합니다.
- **blt 묶음은 기본 끔 (D-14 확정, 3차 검증 받아들임).** 자동 규칙 (REQ · DTYPE · REGEX · ENUM · RANGE) 77개는 지우지 않고 상태 "비활성"으로 두며, `--enable-group blt`로 켤 수 있습니다. blt 교차 규칙은 만들지 않습니다.
- truth 묶음 (부록 A)은 스키마에만 넣고 검사 대상에서 뺍니다. truth 파일 검사는 채점기 몫 (T3 이후)입니다. T6는 truth 파일을 만들지도 읽지도 않습니다.

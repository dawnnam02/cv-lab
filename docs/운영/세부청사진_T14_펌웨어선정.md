## 1. 목적

사용자 프린터가 지금 어떤 펌웨어로 도는지 알아냅니다. G코드 헤더로 먼저 추정하고, 사용자 확인으로 굳힙니다.
층마다 스캔하는 이 워크플로우에 필요한 펌웨어 기능 7가지로 후보를 비교해 하나를 고릅니다.
고른 펌웨어가 실제로 내는 위치·시각 정보가 T1 명세의 허용 값과 T3 시뮬레이터의 위치 로그 모델이 됩니다.
설치·플래싱은 하지 않습니다 (가상 단계 비범위). 실측 전환 때 쓸 절차만 적어 둡니다.

## 4. 산출 문서의 필수 목차

절 제목의 번호는 그대로 둡니다 (검증 명령이 번호로 절을 자릅니다).

```
# 프린터 펌웨어 선정
## 0. 요약
## 1. 현재 펌웨어
## 2. 이 워크플로우가 펌웨어에 요구하는 것
## 3. 후보
## 4. 비교표
## 5. 점수와 선정
## 6. 추가 비용과 예산
## 7. 층 변경 매크로 초안
## 8. T1에 줄 필드
## 9. T2 펌웨어 요구 대조
## 10. T3 위치 로그 모델
## 11. 실측 전환 때 할 일
## 12. 출처
## 13. 한계
```

| 절 | 내용 |
|---|---|
| 0. 요약 | 선정 1개 (조건부면 조건), 이유 3줄, 사용자에게 확인할 것, 예산 영향 한 줄 |
| 1. 현재 펌웨어 | §5.3 추정 규칙으로 뽑은 단서 표 `\| 줄 \| 원문 \| 가리키는 것 \|`, 추정 결과, 확신 수준, 사용자 확인 여부 |
| 2. 요구 | §5.1 기준 7개를 이 워크플로우 말로 다시 씀. 기준마다 관련 MF ID |
| 3. 후보 | 후보마다 한 줄 설명, 판 (버전), 공식 문서 링크 |
| 4. 비교표 | §5.1 형식. 첫 열은 기준 이름, 열마다 후보 |
| 5. 점수와 선정 | §5.2 가중치표, 점수표, 탈락 조건 적용, `선정: <이름>` 한 줄, 이유, 차점과 차이 |
| 6. 추가 비용 | `\| 품목 \| 필요한 후보 \| 가격 \| 근거 \|`, 합계, 상한 95.6만 원 + 추가 ≤ 100만 원 여부, D-12 표시 |
| 7. 매크로 초안 | 코드 블록 1개 이상 + 줄별 설명 표. 슬라이서 층 변경 G코드 칸에 넣는 한 줄 |
| 8. T1 필드 | `\| 필드 \| 명세에 있나 \| 바꿀 내용 또는 새 필드 뜻·단위·자료형 \|`. 첫 칸은 백틱 `묶음.필드` |
| 9. T2 대조 | `\| T2 요구 (기능) \| MF ID \| 선정 펌웨어 \| 남는 대책 \|`. 선정 펌웨어 칸은 충족·부분·불가 |
| 10. T3 모델 | `\| 위치 출처 \| pos.source \| 지연 \| 지터 \| 갱신 주기 \| 근거 \|` |
| 11. 실측 전환 | 단계표 `\| 단계 \| 할 일 \| 실패 위험 \| 확인 방법 \|` |
| 12. 출처 | `\| 번호 \| 제목 \| URL \| 확인 수준 \| 쓰인 칸 \|` |
| 13. 한계 | 확인 못 한 칸, 추정 비중, 실기 미시험 부분 |

## 5. 판정 기준

### 5.1 비교 기준 7개

| 기준 | 묻는 것 | 가능 | 부분 | 불가 | 관련 |
|---|---|---|---|---|---|
| 층 변경 매크로 | 층이 바뀔 때 스캔 동작 (이동·대기·기록·복귀)을 끼워 넣을 수 있나. 변수·조건문·반복이 되나 | 펌웨어 매크로로 전부 | 슬라이서 층 변경 G코드로만 (변수 없음) | 끼워 넣기 불가 | MF-SYN-07 · CK-SYN-12 |
| 실제 위치 보고 | 축 위치를 어떤 출처 (명령·계획·스텝 기준)로, 얼마나 늦게 주나. 이동 완료 대기 명령이 있나 | 스텝 기준 또는 실시간 위치 + 시각 | 명령·계획 위치만. 이동 완료 대기 뒤 확인 | 위치 조회 불가 | MF-SYN-02 · 08 · CK-SYN-13 |
| 카메라 동기화 (트리거·시각) | 이동과 맞춘 트리거 출력 (보드 핀 펄스)을 낼 수 있나. 위치에 프린터 시계 시각을 붙일 수 있나 (`pos.clock` = mcu, `frame.trigger_mode` = hw) | 이동과 맞춘 트리거 + 시각 | 호스트 시계 시각만 (소프트웨어) | 둘 다 불가 | MF-SYN-01 · 03 · 11 · CK-SYN-14 |
| 호스트 연동 | PC 프로그램이 상태 조회·명령·알림을 받을 수 있나 (API · 웹소켓 · 직렬) | 공식 API + 알림 | 직렬 명령·응답만 | 없음 | MF-SYN-10 |
| BLTouch 지원 | BLTouch V3.1 프로빙, 반복성 시험 명령, 점마다 트리거 Z 기록 | 내장 + 반복성 시험 + 점 기록 | 일부만 | 불가 | MF-BLT 범주 |
| 설치 난이도 | 사용자 보드에 설치·되돌리기 과정, 필요한 도구, 실패 위험 | 설정 파일만 바꿈 | 빌드·플래싱 필요 | 사용자 보드 미지원 | D-10 |
| 추가 비용 | 새로 사야 할 장치와 가격 | 0원 | 상한 안 (95.6만 + 추가 < 100만) | 상한 넘음 (D-12) | §6 |

- 칸에는 "가능·부분·불가·미상" 중 하나 + 한 줄 설명 + 근거 태그를 씁니다. 예: `가능. 매크로에 변수·조건문 [출처 3]`.
- 사용자 보드를 모르면 "설치 난이도"는 일반 보드 기준으로 쓰고 `[미상] 사용자 보드`를 덧붙입니다.

### 5.2 가중치와 탈락

| 기준 | 가중치 | 비고 |
|---|---|---|
| 층 변경 매크로 | 3 | **불가면 탈락** |
| 실제 위치 보고 | 3 | **불가면 탈락** |
| 카메라 동기화 | 3 | 부분이어도 남음 (호스트 시각으로 대신, U 예산에 지연 몫을 더함) |
| 호스트 연동 | 2 | |
| BLTouch 지원 | 2 | |
| 설치 난이도 | 2 | |
| 추가 비용 | 2 | 상한을 넘어도 탈락은 아님. D-12로 본인에게 넘김 |

- 점수: 가능 2 · 부분 1 · 불가 0 · 미상 0 (미상은 13절 한계에 적고 확인 계획을 씀). 합계 = Σ 가중치 × 점수, 만점 34.
- 합계 차이가 3점 이하이면 동점으로 보고, 사용자 현재 펌웨어를 우선합니다 (교체 위험·비용이 없음).

### 5.3 G코드 헤더 추정 규칙 (팀장 초안, worker가 확인 후 사용)

아래는 팀장이 경험으로 적은 단서입니다. **확인 전입니다.** worker가 슬라이서 문서로 확인한 것만 1절 근거로 씁니다.

| 단서 (G코드 안) | 가리키는 것 | 주의 |
|---|---|---|
| 끝부분 설정 블록의 `; gcode_flavor = …` (PrusaSlicer · OrcaSlicer 계열) | 슬라이서에 설정한 방언 | 실제 펌웨어와 다를 수 있음 |
| 머리말 `;FLAVOR:…` (Cura 계열) | 같음 | Klipper 프린터에도 Marlin 방언을 흔히 씀 |
| `; generated by …` · `printer_model` · `printer_settings_id` | 슬라이서 이름·판, 프린터 프로필 | 프린터 기종 추정의 출발점 |
| 대문자 매크로 호출 (`PRINT_START` · `START_PRINT`), `EXCLUDE_OBJECT_DEFINE`, `SET_PRINT_STATS_INFO` | Klipper 가능성 | 매크로 이름은 사용자 정의 |
| `M98 P"…"` 매크로 호출, RRF식 도구 온도 `G10 P… S…` | RepRapFirmware 가능성 | |
| `M486` (객체 표시), `G29` · `M420` (메시) | Marlin 계열 가능성 | RRF도 `G29`를 씀 |
| 제조사 전용 슬라이서 표기 (예: Bambu Studio) | 제조사 전용 펌웨어 | 교체 불가 가능성. 후보에 추가 (FW2) |

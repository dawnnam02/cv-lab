## 1. 목적

하드웨어가 있었다면 나왔을 데이터를 **원시 카메라 영상부터** 만듭니다. 순서는 아래와 같습니다.

```
G코드 (D-19 두 파일 + plate20) ─ 파싱 (cvlab.gcode) ─▶ 참 출력 형상 (층마다, 측정 당시 열 상태)
   + T5 시나리오 (출력 오차)  + 열 모델 (층 온도 · 수축)  + Z축 · 프레임 · 브래킷 오차
                                   │
                                   ▼
레이저 선 렌더 (빔 · 표면 반사 · 표면 아래 산란 · 스펙클 · 가림 · 광택) ─▶ 카메라 원시 영상 (렌즈 · 잡음 · 8비트 ROI)
                                   │
위치 로그 (SV08 · Klipper, LM-T14-3 매크로 이벤트, 트리거 펄스) ─┤
교정 원자료 (ChArUco · 레이저 평면 · 스캔 축 · 노즐-센서 · 필러게이지 · 계단 기준물 · 재료 조각) ─┤
기준 · 반복 (베드 기준 · 계단 기준물 두 개 · 정지 반복 · 같은 층 반복 · 식힌 재측정) ─┤
                                   ▼
          명세 (T1 v1.0) 형식 data/raw/<campaign>/   ·   참값 data/_truth/<campaign>/ (따로)
```

이 데이터로 처리 코드의 정확도 (C4 · C5)와 판정 정확도 (C12)를 참값과 비교해 증명합니다. **해석 주의:** 가상 데이터의 결과는 "알고리즘이 시뮬레이터가 넣은 오차를 얼마나 복원하는가"이며 하드웨어 성능의 증거가 아닙니다 (청사진 §2.2).

### 6.8 시드와 재현

- 시드 나무: 캠페인 시드 → 시편 → 층 → 스캔 (줄 · 반복) → 성분 (스펙클 · 잡음 · 지터). `numpy.random.SeedSequence`의 `spawn` 또는 키 해시로 갈래를 만들어, **처리 순서 · 작업자 수와 무관하게** 같은 값이 나오게 함.
- 벽시계를 쓰지 않음: `meta.datetime` · `cal.created` · `t_ns`는 캠페인 시작 시각 (설정값)에서 가상 시계로 셈. `meta.software_git`은 실행한 커밋 (같은 커밋끼리만 재현 비교).
- PNG는 압축 수준 · 필터를 고정하고 시각 조각 (tIME 등)을 넣지 않음. JSON 키 순서 · 소수 자릿수 고정 (명세 0.5절 정밀도 규칙).
- 재현 시험: 작은 캠페인을 같은 시드로 두 번 → 모든 파일 sha256 같음. `--workers 1`과 `--workers 4` 결과도 같음.
- 이 PC는 `core.autocrlf` = true입니다. 재현 비교는 생성한 파일끼리 하고, Git으로 꺼낸 텍스트와 비교하지 않습니다 (팀장검증 4차 §5.2: plate20이 git archive에서 CRLF로 바뀜).

### 6.9 블라인드 평가 세트

- 생성 경로: `scripts/sim_generate.py --eval --campaign <설정>`. 시드는 `CVLAB_EVAL_SEED`에서만 읽음. 시나리오 배정 · 강도는 T5 §8 원칙 (종류마다 P · B · F 고르게, 범위 안 무작위, 경계는 보류 띠 근처, 두 종류 겹친 행 일부)을 시드로 뽑음.
- raw 쪽: `meta.blind` = true (캠페인 모든 스캔 같은 값), `meta.sim_seed` null, `meta.injected_factors` [], `rep.noise_seed` 빈 칸 (명세 v1.0). 참값 쪽: `truth.seed` · `truth.scan_seeds` (스캔마다 sim_seed · noise_seed) · `truth.scan_factors` (스캔마다 요인 ID) · `truth.factor_params` (강도, 키 = scan_factors 합집합).
- 시뮬레이터 담당은 평가용 세트를 만들지 않습니다 (경로와 시험만). 팀장이 게이트 때 직접 만듭니다.

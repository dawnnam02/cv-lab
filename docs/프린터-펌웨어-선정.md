## 0. 요약

- **최종 1순위: Voron Trident (LDO 키트, 300 mm) + Klipper (mainline)** · 조합 점수 65/74.
- 이유 1: 스캔 축 (Y)으로 베드가 움직이지 않고 (베드는 Z만), Z를 리드스크루 3개·모터 3개로 받쳐 `Z_TILT_ADJUST`로 자동 수평을 맞춤 [출처 13].
- 이유 2: mainline Klipper라 변수·조건문 매크로, `M400`, `GET_POSITION` (스텝 기준), `motion_report` 실시간 위치, Moonraker 구독 API가 모두 열려 있음 [출처 1, 2, 3, 6, 21].
- 이유 3: 설계·CAD가 공개돼 센서 브래킷을 설계하기 쉽고, 접촉식 프로브 (Tap 또는 BLTouch)를 공식·표준 방법으로 달 수 있음 [출처 9, 11, 4].
- 차점 Voron 2.4 (65/74, 같은 점수). 구조·개조비가 같아 본체 가격으로 갈랐음. 그다음 Sovol SV08 (59/74).
- 가격대별 추천: 50만 이하 = Ender-3 V3 SE + Klipper 교체 (48/74) · 50~100만 = Sovol SV08 + Klipper 그대로 (59/74) · 100만 초과 = Voron Trident + Klipper (65/74).
- 예산 (측정 장비 + 개조비): Trident·SV08은 명목 57만 · 상한 97.6만으로 100만 원 안. Ender-3 V3 SE는 상한 107.6만으로 넘음 → D-12. 본체 가격은 따로.
- 사용자에게 확인할 것: ① 본체 예산 (D-13) ② G코드를 슬라이스한 프린터 프로필 (D-10) ③ 구입 시점 ④ 키트 조립 (Voron은 직접 조립, 수십 시간 [추정])을 감수할지.

## 1. 출발 상태

- 사용자 지시 원문 (10-27): "펌웨어 선정해. 프린터 기종도 선정해 완벽한 걸로."
- **사용자 프린터 없음 (10-27)**. 정해진 기종이 없으므로 프린터와 펌웨어를 함께 고름.
- M03 정정: M03의 "보유 프린터에 BLTouch V3.1, Klipper"는 사실이 아님. 보유 프린터는 없음. M03 비용 5만 원은 "BLTouch 단품 가격"으로만 보고, 측정 장비 명목 55만에 그대로 둠. 고른 기종에 접촉식 프로브가 기본으로 있으면 (Tap·로드셀) BLTouch가 필요 없을 수 있으나, 출력물 윗면 검증 (C7) 비교를 위해 BLTouch는 유지함 (8절).
- 사용자 G코드: 받지 못함. 슬라이스 프로필 `[미상] (D-10 대기)`. 검증 명령 ①은 돌리지 않음.

| 줄 | 원문 | 가리키는 것 |
|---|---|---|
| - | G코드 없음 [미상] (D-10 대기) | 받으면 §5.5 규칙으로 채움 |

- 다시 슬라이스 필요 여부: [미상]. G코드가 Trident (Klipper) 프로필이 아니면 "다시 슬라이스 필요"를 T4·T5에 넘김. 층 변경 칸에 9절의 한 줄을 넣어야 하므로, 어느 프로필이든 최소한 층 변경 G코드는 다시 넣어야 함 [추정].

## 2. 이 워크플로우가 프린터·펌웨어에 요구하는 것

층마다 출력이 끝나면 노즐을 비키고, 툴헤드 옆 레이저 센서 (M54)로 방금 쌓은 윗면을 Y 방향 2.4 mm/s · 40 mm로 한 번 훑음. 그 프레임마다 정확한 Y 위치와 시각이 붙어야 하고, 센서-윗면 거리 (Z)가 층마다 믿을 만해야 함.

최종 1순위: Voron Trident (LDO 키트 300) + Klipper (mainline)

- 이유 1. 스캔 중 시편이 움직이지 않음 (베드는 Z만). Z를 3점에서 따로 구동하고 출력마다 Z_TILT로 맞춤 [출처 13]. 층마다 센서-윗면 거리 기준이 흔들릴 원인이 가장 적은 구조.
- 이유 2. mainline Klipper라 제조사 포크의 판 차이 걱정이 없음. 매크로 (Jinja2), M400, GET_POSITION 스텝 기준 위치, motion_report, Moonraker 구독이 공식 문서대로 동작 [출처 1, 2, 3, 6, 21].
- 이유 3. 설계가 공개돼 센서 브래킷을 툴헤드에 맞춰 설계할 수 있고, Tap·BLTouch를 표준 방법으로 닮 [출처 9, 11, 4]. 키트에 Pi 4B가 들어 있어 호스트 개조비가 없음 [출처 15].
- 차점과 차이: Voron 2.4도 65/74로 같음. §5.3 규칙 ① 구조 점수 같음 (6 = 6) → ② 개조비 같음 (2만 = 2만 [추정]) → ③ 본체 가격: 같은 판매처 기준 Trident 300이 1,969 AUD, 2.4 350이 2,295 AUD로 Trident가 쌈 [출처 14, 15]. 같은 크기끼리 비교는 [미상].
- 정성 비교: Trident의 리드스크루 Z는 전원을 꺼도 처지지 않고, 2.4의 벨트 Z는 끌 때 갠트리가 처져 매번 QGL이 필요함 [출처 13]. 대신 리드스크루 휨·너트 유격 (MF-MEC-04)은 Trident 쪽 위험.
- 3위 SV08 (59/74)과의 차이 6점: 센서 장착 (CAD 미상), 프로브 (유도형), 카메라 연결 (호스트 사양 미상)에서 갈림.

## 9. 층 변경 매크로 초안

최종 1순위 조합 (Voron Trident + mainline Klipper) 문법. **실기 미시험.** 층 번호는 0부터. 주석은 ASCII.
설계 원칙: Klipper 매크로는 실행 전에 통째로 평가되므로 [출처 3], 매크로 안에서 위치를 변수로 읽지 않음. 위치·시각은 `GET_POSITION`·`M118` 출력과 Moonraker 구독 (eventtime)으로 PC가 기록함 [출처 1, 21].

printer.cfg에 더할 부분:

```ini
# --- T14 draft: layer-end laser scan (NOT tested on hardware) ---
[respond]

[output_pin cam_gate]
# pick a free pin on the board; PG14 is a placeholder only
pin: PG14
value: 0

[gcode_macro SCAN_LAYER]
description: Layer-end laser scan, layer index starts at 0 (draft)
variable_every_n: 5
variable_scan_x: 110.0
variable_scan_y0: 90.0
variable_scan_len: 40.0
variable_scan_speed: 2.4
variable_lead_in: 5.0
variable_z_hop: 2.0
variable_retract: 0.8
gcode:
  {% set layer = params.LAYER|int %}
  {% set v = printer["gcode_macro SCAN_LAYER"] %}
  {% if layer >= 0 and layer % v.every_n == v.every_n - 1 %}
    {# 0. mark layer #}
    SET_PRINT_STATS_INFO CURRENT_LAYER={layer}
    M118 SCAN layer={layer} event=layer_change
    SAVE_GCODE_STATE NAME=scan_state
    {# 1. move nozzle away: retract and lift #}
    M83
    G1 E-{v.retract} F1800
    G91
    G1 Z{v.z_hop} F600
    G90
    {# 2. go to scan start minus lead-in #}
    G1 X{v.scan_x} Y{v.scan_y0 - v.lead_in} F6000
    {# 3. wait until all moves are done #}
    M400
    M118 SCAN layer={layer} event=m400_done
    GET_POSITION
    {# 4. open camera gate and run constant speed scan #}
    SET_PIN PIN=cam_gate VALUE=1
    M118 SCAN layer={layer} event=scan_start
    G1 Y{v.scan_y0 + v.scan_len} F{v.scan_speed * 60}
    M400
    {# 5. close gate and log end #}
    SET_PIN PIN=cam_gate VALUE=0
    M118 SCAN layer={layer} event=scan_end
    GET_POSITION
    {# 6. return to print position and unretract #}
    RESTORE_GCODE_STATE NAME=scan_state MOVE=1 MOVE_SPEED=100
    SAVE_GCODE_STATE NAME=unretract_state
    M83
    G1 E{v.retract} F1800
    RESTORE_GCODE_STATE NAME=unretract_state
    M118 SCAN layer={layer} event=resume
  {% endif %}
```

| 줄 (단계) | 하는 일 | 근거 |
|---|---|---|
| `[respond]` | M118 응답 출력을 켬 (Klipper에서 M118은 respond 모듈 [추정]) | [출처 1] M118 목록 |
| `[output_pin cam_gate]` | 카메라 게이트 신호용 출력 핀. 핀 이름은 보드 여분 핀으로 바꿈 | [출처 1] SET_PIN |
| `variable_*` | 스캔 X 110 mm, 시작 Y 90 mm, 길이 40 mm, 2.4 mm/s, 도움닫기 5 mm, Z 올림 2 mm (C2 권장) | M54, C2, 명세 `meta.scan_*` |
| `params.LAYER` 조건 | 층 번호 0부터. `every_n` = 5면 층 4·9·14…를 잼 (C2 N = 5) | C2 |
| 0. 층 표시 | `SET_PRINT_STATS_INFO`로 Klipper에 층 번호를 넣고 로그에 layer_change | [출처 1, 2] |
| 1. 노즐 비킴 | 리트랙트 0.8 mm, Z 2 mm 올림 (상대 좌표) | [출처 1] |
| 2. 스캔 시작 위치 이동 | 시작 Y에서 도움닫기 5 mm 앞으로 감 (MF-MEC-02 링잉, MF-SYN-08 가속 구간) | MF-MEC-02 · MF-SYN-08 |
| 3. 이동 완료 대기 | `M400`으로 큐를 비움 → `GET_POSITION`으로 정지 위치 (mcu·stepper·toolhead·gcode)를 기록 | [출처 1, 6] |
| 4. 위치·시각 기록과 등속 스캔 | 게이트 핀을 올리고 scan_start 기록 → Y 40 mm 등속 이동 | [출처 1] |
| 5. 끝 기록 | `M400` 뒤 게이트 내림, scan_end와 정지 위치 기록 | [출처 1, 6] |
| 6. 복귀·재개 | 저장한 좌표·모드로 복귀 (MOVE=1), 상대 E로 언리트랙트 뒤 모드만 다시 복원 | [출처 1] |

- 게이트 핀은 스캔 동안 높음. 프레임마다 트리거가 아니므로 `frame.trigger_mode`는 free (카메라 자유 실행) + 게이트 엣지로 시작·끝 시각을 맞춤 (10절). 게이트가 이동 큐와 어떻게 맞춰지는지는 [추정]이고 실기 시험 필요 (13절 9단계).
- 도움닫기 5 mm 안의 프레임은 Y < scan_y0이라 버림. 
- 메시 보정은 스캔 중에도 켜져 Z가 메시대로 움직임 (fade 기본 꺼짐 [출처 5]). 스캔 구간 메시 Z 보정은 `pos.mesh_dz_mm`로 남김 (MF-MEC-07).

슬라이서 층 변경 칸에 넣는 한 줄 (PrusaSlicer·OrcaSlicer "Before layer change G-code"):

```gcode
SCAN_LAYER LAYER={layer_num - 1}
```

- 층 변경 "전" 칸은 다음 층이 시작되기 직전에 돌기 때문에 방금 끝난 층은 `layer_num - 1`로 봄 [추정, 슬라이서 문서 미확인]. 한 층 어긋나면 기준 대비 0.2 mm 오차 (MF-SYN-07)라, 13절 9단계에서 층 번호를 실제로 대조함.
- Trident 시작 매크로 (PRINT_START)에 넣을 곳: `G28` → `Z_TILT_ADJUST` → `G28 Z` → `BED_MESH_CALIBRATE` 다음, 퍼지 선 전에 `SET_PIN PIN=cam_gate VALUE=0`과 `M118 SCAN event=print_start`를 둠. 메시 프로필 이름과 `printer.bed_mesh` 범위를 이때 PC가 받아 `meta.mesh_enabled`와 함께 남김 [출처 2].
- `M84` (모터 끄기)는 넣지 않음 (MF-SYN-09).

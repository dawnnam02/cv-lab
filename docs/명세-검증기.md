## 1. 실행법

Git Bash에서 저장소 뿌리 기준입니다. 설치 명령은 없습니다 (`requirements.txt`의 7개가 이미 깔려 있어야 함).

```bash
# 환경 점검 (판이 다르면 종료 코드 1)
PYTHONIOENCODING=utf-8 python scripts/check_env.py

# 명세 → 스키마·규칙표 다시 뽑기
PYTHONIOENCODING=utf-8 PYTHONPATH=src python scripts/extract_spec_schema.py
PYTHONIOENCODING=utf-8 PYTHONPATH=src python scripts/extract_spec_schema.py --check          # 저장본과 같은지만

# 캠페인 검사
PYTHONIOENCODING=utf-8 PYTHONPATH=src python scripts/validate_dataset.py data/raw/VC-2026-11-20-A --report out.json
# 기본 끔 규칙 켜기 (D-21 대기: W-REF-11 = 판정 거부 X4, W-MET-56 = X7). 켜도 WARN이라 종료 코드는 그대로
PYTHONIOENCODING=utf-8 PYTHONPATH=src python scripts/validate_dataset.py data/raw/VC-… --enable-rule W-REF-11 --enable-rule W-MET-56
# 저장소 뿌리를 직접 줌 (meta.gcode_file · meta.slicer_profile_file 검사, FILE-17 · 18)
PYTHONIOENCODING=utf-8 PYTHONPATH=src python scripts/validate_dataset.py /어딘가/VC-… --repo-root .

# 자체 시험 (정상·경계·고장 표본)
PYTHONIOENCODING=utf-8 PYTHONPATH=src python scripts/validate_dataset.py --selftest --report "$TEMP/t6_selftest.json"

# 시험
PYTHONIOENCODING=utf-8 PYTHONPATH=src python -m pytest tests/infra -q -p no:cacheprovider
```

| 종료 코드 | 뜻 |
|---|---|
| 0 | ERROR 0건 (WARN은 있어도 됨) |
| 1 | ERROR 1건 이상 (자체 시험이면 하나라도 놓침) |
| 2 | 사용법 오류 (모르는 `--enable-rule` ID 포함), 폴더 없음, 스키마 파일 없음, 명세 지문이 `SOURCE.txt`와 다름, `_truth` 경로, `config/default.yaml` 못 읽음 |

**기본 끔 규칙 스위치.** 어디에 적어도 켜집니다 (합침).

| 스위치 | 쓰는 법 |
|---|---|
| 명령줄 | `--enable-rule W-REF-11` (여러 번 쓸 수 있음) |
| 설정 | `config/default.yaml`의 `validate.enable_rules: [W-REF-11, W-MET-56]` (지금 `[]`) |
| Python | `Validator(fields, rules, file_cols, enabled_rules={"W-REF-11"})` |

**저장소 뿌리.** `meta.gcode_file`·`meta.slicer_profile_file`은 저장소 뿌리 기준 경로입니다 (명세 0.1절). 캠페인 폴더가 `<뿌리>/data/raw/<campaign_id>`이면 그 `<뿌리>`를 씁니다. 그 모양이 아니고 `--repo-root`도 없으면 FILE-17 · 18을 건너뜁니다 (임시 폴더에 쓴 표본 등).

보고 JSON의 `findings` 행마다 `rule_id · severity · file · row · field · value · message`가 있습니다. `row`는 CSV 줄 번호 (머리글 = 1), 파일 전체 규칙이면 `null`입니다.

Python에서 쓸 때:

```python
from cvlab.io.schema_files import load
from cvlab.io.validate import DirFS, Validator
fields, rules, file_cols = load()
v = Validator(fields, rules, file_cols, repo_root=".")
findings = v.run(DirFS("data/raw/VC-2026-11-20-A"), "VC-2026-11-20-A")
truth_findings = v.check_truth({"judgement": "pass", "pass_pct": 97.0})   # 참값 객체 (T3), 파일은 열지 않음
```

## 2. 스키마 추출 규칙

`scripts/extract_spec_schema.py` → `cvlab.io.spec_schema.extract()`. 손으로 옮기지 않습니다.

| 열 | 뽑는 법 |
|---|---|
| `field` … `rule_text` | 명세에서 `` ^\| `(frame\|pos\|cal\|ref\|meta\|blt\|rep\|truth)\.[a-z0-9_]+` \| `` 인 행. `' \| '`로 나눈 칸이 7개가 아니면 추출 실패 (종료 코드 2). 13절 "제외한 필드" 표는 첫 칸이 `blt (D-14)`라 필드로 읽지 않음 |
| `regex` | "정규식 `…`" (+ "또는 `…`")의 식. 여러 개면 `\|\|`로 잇고 하나라도 맞으면 통과. 조건이 붙은 정규식 ("…면 정규식")은 뽑지 않음 |
| `enum` · `enum_pending` | "값 ∈ {…}" 목록 (쉼표로 나눔), 문장 전체가 "값 = v"면 그 하나. 뒤에 `[대기: T14]`가 붙으면 `enum_pending = true` → 그 ENUM 규칙은 WARN. T1 2차에서 표시가 모두 풀려 지금은 0개 |
| `min` · `min_op` · `max` · `max_op` | 문장 단위로 "a ≤ x ≤ b", "0 < x", "x ≥ c", "abs(x) ≤ c", "= v". 끝값이 다른 필드면 비우고 CROSS 규칙이 맡음. "…면 x ≥ 100"처럼 조건이 붙은 범위는 뽑지 않음. 유니코드 빼기 (−)는 `-`로, `2^63`은 정수로 |
| `file` | 묶음별 파일 (§0.2). cal·rep는 파일이 둘이라 `;`로 이음. `cal_results.csv` 열 목록은 명세 3절 문장에서 뽑음 |
| `excluded` · `excluded_reason` | 명세가 묶음을 제외로 표기하면 true, 사유는 명세 절 (`명세 6절 제외 표기 (D-14)`). 표기 형식은 절 제목 `## 6. … (blt) — 제외 (D-14)` 또는 본문 줄 첫머리 `제외 묶음: blt.` 둘 다. 명령줄 `--exclude-groups`는 명세 표기가 없을 때만 씀 (기본 blt). 지금 blt 필드 행이 없어 모든 행이 false |
| `order` | 필드표 순서 (CSV 열 순서 검사에 씀) |

- `config/spec/SOURCE.txt`에 명세 SHA-256, 뽑은 시각, 묶음별 필드 수, 제외 묶음과 사유, 규칙 수 (상태별)를 적습니다. fields·rules CSV는 두 번 뽑아도 같은 바이트입니다 (시험 `test_extract_is_deterministic`).
- 명세 지문이 `SOURCE.txt`와 다르면 `test_infra_schema_sync`가 실패하고 검증기는 종료 코드 2로 멈춥니다.
- 고정 파일 이름 (명세 8절): `meta.json` · `frames_index.csv` · `position_log.csv` · `cal_manifest.csv` · `cal_results.csv` · `ref_index.csv` · `design.csv` · `design_executed.csv` (+ 참값 쪽 `truth.json`). `probe_points.csv` · `probe_accuracy.csv`는 T1 2차에서 빠짐.

**문장 연결 방식.** 검사 대상 필드의 "검증 규칙" 칸을 문장 (`. ` 기준)으로 나누고, 문장마다 맡은 규칙을 찾습니다 (`rules.classify_sentences`). 자동 규칙이 맡는 문장은 모양으로 알아보고, 나머지는 손 규칙의 `covers` (필드 + 문장 일부)로 잇습니다. 검사할 내용이 없는 설명문 37개는 사유와 함께 `rules.NOTES`에 둡니다 (예: "SV08 = corexy" 기종별 값 예시, "판을 모르면 unknown" 작성 안내, "판정에는 in_process만" 판정 단계 몫). 연결되지 않은 문장이 하나라도 있으면 추출 스크립트가 종료 코드 1, 시험 `test_no_unclassified_sentence`가 실패합니다. `covers`의 글자가 명세 문장에 실제로 있는지도 시험합니다 (`test_every_cover_snippet_is_used`).

## 7. 명세가 바뀌면 할 일

1. `PYTHONPATH=src python scripts/extract_spec_schema.py`로 다시 뽑습니다. 미분류 문장이 있으면 목록이 나오고 종료 코드 1입니다.
2. 미분류 문장마다 `src/cvlab/io/rules.py`에 손 규칙 (`_h(...)`, `covers`에 필드:문장 일부), 보류 (사유 필수), 설명문 (`NOTES`) 중 하나를 더합니다. 새 조건부 필드는 `CONDITIONS`와 `validate.COND_FUNCS`에 같은 키로 넣습니다.
3. 새 손 규칙은 `validate.py`에 `emit("ID", …)`로 구현하고 (ID를 글자 그대로 써야 시험이 찾음), `selftest.py`에 고장 표본을 하나 더합니다.
4. 사용자 결정을 기다리는 규칙은 상태 `비활성`, 사유에 결정 번호와 켜는 법을 적고 `selftest.switch_tests()`에 표본을 넣습니다.
5. `--selftest`와 `pytest tests/infra`를 돌려 정상 0 · 경계 0 · 탐지 100 %를 확인합니다.
6. 바뀐 필드·규칙을 대조표에 적습니다.
7. **D-21이 정해지면**: X4 · X7을 채택하면 `rules.py`의 W-REF-11 · W-MET-56 상태를 `구현`으로 (판정 거부면 심각도 ERROR로) 바꾸고 다시 뽑습니다. 채택하지 않으면 규칙을 지우고 명세 문장을 설명문으로 옮깁니다.

## 8. 한계

**검증기 자체의 한계**

- 문장 연결은 "그 문장을 맡은 규칙이 있다"까지 기계로 확인합니다. 규칙이 문장 뜻을 정확히 옮겼는지는 사람이 봐야 합니다 (팀장 검사 §8.2 무작위 10행).
- 조건부 필드 가운데 `frame.t_cam_ns` · `frame.cam_seq` ("카메라가 주면")는 파일 안 한 행이라도 값이 있으면 모든 행 필수로 읽었습니다. `meta.camera_temp_c`는 실측이면 센서 유무를 몰라 선택으로 둡니다.
- X-MET-07 · X-MET-55 · W-MET-56은 같은 세션의 **같은 시편·반복** 안에서만 봅니다.
- 스캔 구간 규칙 (X-POS-03 ~ 07 · 12)은 호스트 시각으로 바꾼 scan_start ~ scan_end 사이 행만 봅니다. `pos.clock = mcu`인데 `clock_offset_ns`가 빈 행은 구간 판정에서 빠집니다.
- X-REF-16 (같은 Z)은 두 위치 로그의 스캔 구간 명령 Z (`source = cmd`) 평균을 비교합니다. 기준 로그에 scan_start·scan_end가 없으면 그 로그의 모든 cmd 행을 씁니다.
- X-CAL-22는 `GB-` 뒤 두 자리 숫자를 mm로 읽어 더합니다 (명세 3절 "GB-<높이 mm 2자리>, 쌓으면 +"). 0.02 mm 폭은 명세 [추정]입니다.
- 기준 폴더의 위치 로그는 형식 (자동 규칙)과 X-POS-11 · X-REF-16만 봅니다. 스캔 폴더 위치 로그의 구간 규칙 (X-POS-02 ~ 14)은 돌리지 않습니다 (명세가 기준 로그에 요구하는 것은 scan_id · layer_idx · 같은 Z뿐).
- X-TRU-01은 `data/raw` 검사에 들지 않습니다. 참값을 쓰는 쪽 (T3)이 `Validator.check_truth()`를 불러야 합니다.
- `frames.npz` 대안 저장은 키가 있는지만 봅니다.
- 디스크 폴더를 읽을 때 Windows 백신 검사로 새 파일 열기가 느립니다 (파일 하나 약 50 ms). 자체 시험은 정상 표본만 디스크에 한 번 쓰고 나머지는 메모리에서 돌립니다.

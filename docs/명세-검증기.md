## 1. 실행법

Git Bash에서 저장소 뿌리 기준입니다. 설치 명령은 없습니다 (`requirements.txt`의 7개가 이미 깔려 있어야 함).

```bash
# 환경 점검 (판이 다르면 종료 코드 1)
PYTHONIOENCODING=utf-8 python scripts/check_env.py

# 명세 → 스키마·규칙표 다시 뽑기 (blt는 기본으로 꺼짐)
PYTHONIOENCODING=utf-8 PYTHONPATH=src python scripts/extract_spec_schema.py
PYTHONIOENCODING=utf-8 PYTHONPATH=src python scripts/extract_spec_schema.py --check          # 저장본과 같은지만
PYTHONIOENCODING=utf-8 PYTHONPATH=src python scripts/extract_spec_schema.py --exclude-groups ""  # blt도 켬

# 캠페인 검사
PYTHONIOENCODING=utf-8 PYTHONPATH=src python scripts/validate_dataset.py data/raw/VC-2026-11-20-A --report out.json
PYTHONIOENCODING=utf-8 PYTHONPATH=src python scripts/validate_dataset.py data/raw/VC-… --enable-group blt   # blt 파일도 검사

# 자체 시험 (정상·경계·고장 표본)
PYTHONIOENCODING=utf-8 PYTHONPATH=src python scripts/validate_dataset.py --selftest --report "$TEMP/t6_selftest.json"

# 시험
PYTHONIOENCODING=utf-8 PYTHONPATH=src python -m pytest tests/infra -q -p no:cacheprovider
```

| 종료 코드 | 뜻 |
|---|---|
| 0 | ERROR 0건 (WARN은 있어도 됨) |
| 1 | ERROR 1건 이상 (자체 시험이면 하나라도 놓침) |
| 2 | 사용법 오류, 폴더 없음, 스키마 파일 없음, 명세 지문이 `SOURCE.txt`와 다름, `_truth` 경로 |

보고 JSON의 `findings` 행마다 `rule_id · severity · file · row · field · value · message`가 있습니다. `row`는 CSV 줄 번호 (머리글 = 1), 파일 전체 규칙이면 `null`입니다.

Python에서 쓸 때:

```python
from cvlab.io.schema_files import load
from cvlab.io.validate import DirFS, Validator
fields, rules, file_cols = load()
findings = Validator(fields, rules, file_cols).run(DirFS("data/raw/VC-2026-11-20-A"), "VC-2026-11-20-A")
```

## 2. 스키마 추출 규칙

`scripts/extract_spec_schema.py` → `cvlab.io.spec_schema.extract()`. 손으로 옮기지 않습니다.

| 열 | 뽑는 법 |
|---|---|
| `field` … `rule_text` | 명세에서 `` ^\| `(frame\|pos\|cal\|ref\|meta\|blt\|rep\|truth)\.[a-z0-9_]+` \| `` 인 행. `' \| '`로 나눈 칸이 7개가 아니면 추출 실패 (종료 코드 2) |
| `regex` | "정규식 `…`" (+ "또는 `…`")의 식. 여러 개면 `\|\|`로 잇고 하나라도 맞으면 통과. 조건이 붙은 정규식 ("…면 정규식", 예: `blt.face_id`)은 뽑지 않음 |
| `enum` · `enum_pending` | "값 ∈ {…}" 목록 (쉼표로 나눔), 문장 전체가 "값 = v"면 그 하나. 뒤에 `[대기: T14]`가 붙으면 `enum_pending = true` → 그 ENUM 규칙은 WARN |
| `min` · `min_op` · `max` · `max_op` | 문장 단위로 "a ≤ x ≤ b", "0 < x", "x ≥ c", "abs(x) ≤ c", "= v". 끝값이 다른 필드면 비우고 CROSS 규칙이 맡음. "…면 x ≥ 100"처럼 조건이 붙은 범위는 뽑지 않음. 유니코드 빼기 (−)는 `-`로, `2^63`은 정수로 |
| `file` | 묶음별 파일 (§0.2). cal·blt·rep는 파일이 둘이라 `;`로 이음. 파일별 열 구성은 명세 본문 문장에서 뽑음 (`cal_results.csv` 열 목록, `probe_accuracy.csv` 열 목록) |
| `excluded` · `excluded_reason` | 명세가 묶음을 제외로 표기하면 true. 표기 전이라도 `--exclude-groups`로 묶음 단위로 끔. 기본값 `blt` (D-14, 팀장 지시 10-27) |
| `order` | 필드표 순서 (CSV 열 순서 검사에 씀) |

- `config/spec/SOURCE.txt`에 명세 SHA-256, 뽑은 시각, 묶음별 필드 수, 꺼 둔 묶음을 적습니다. fields·rules CSV는 두 번 뽑아도 같은 바이트입니다 (시험 `test_extract_is_deterministic`).
- 명세 지문이 `SOURCE.txt`와 다르면 `test_infra_schema_sync`가 실패하고 검증기는 종료 코드 2로 멈춥니다.

**문장 연결 방식.** 검사 대상 필드의 "검증 규칙" 칸을 문장 (`. ` 기준)으로 나누고, 문장마다 맡은 규칙을 찾습니다 (`rules.classify_sentences`). 자동 규칙 (정규식·허용 값·범위·유한값·빈 문자열·ISO·참거짓)이 맡는 문장은 모양으로 알아보고, 나머지는 손 규칙의 `covers` (필드 + 문장 일부)로 잇습니다. 검사할 내용이 없는 설명문 15개는 사유와 함께 `rules.NOTES`에 둡니다 (예: "M54 기본 +Y", "예시는 자리표시", "단위 프레임/s"). 연결되지 않은 문장이 하나라도 있으면 추출 스크립트가 종료 코드 1, 시험 `test_no_unclassified_sentence`가 실패합니다. `covers`의 글자가 명세 문장에 실제로 있는지도 시험합니다 (`test_every_cover_snippet_is_used`).

## 5. 고장 표본 목록

**표본 값은 형식 시험용입니다. 측정값이 아닙니다.** 모든 표본은 실행할 때 메모리와 임시 폴더 (`tempfile`)에 만들고 지웁니다. 저장소에 커밋하지 않습니다.

**정상 표본** (`cvlab.io.selftest.normal_model`): 부록 B 값을 쓰고 아래만 바꿨습니다.

| 항목 | 부록 B | 정상 표본 | 이유 |
|---|---|---|---|
| 층 수 | 20 (예시는 층 4) | `layer_count` 2, `L000` · `L001` + `post` | 표본 크기 줄임 |
| 스캔 길이·프레임 | 40 mm, 2010장 | `scan_length_mm` 0.2, 10장 + 배경 2장 = `n_frames` 12 | 0.2 ÷ 0.02 = 10 [계산] |
| ROI·영상 | 1280 × 256, GRAY10 | 32 × 16, 8비트 PNG, `bit_depth` 8, `GRAY8` | 명세 "8비트 그릇 PNG면 8" |
| 층 Z·G코드 줄 | 1.0 mm, 4120–5388 | 0.2 · 0.4 mm, 1–100 · 101–200 | 층 높이 0.2 × 층 번호 [계산] |

## 7. 명세가 바뀌면 할 일

1. `PYTHONPATH=src python scripts/extract_spec_schema.py`로 다시 뽑습니다. 미분류 문장이 있으면 목록이 나오고 종료 코드 1입니다.
2. 미분류 문장마다 `src/cvlab/io/rules.py`에 손 규칙 (`_h(...)`, `covers`에 필드:문장 일부), 보류 (사유 필수), 설명문 (`NOTES`) 중 하나를 더합니다. 새 조건부 필드는 `CONDITIONS`와 `validate.COND_FUNCS`에 같은 키로 넣습니다.
3. 새 손 규칙은 `validate.py`에 `emit("ID", …)`로 구현하고, `selftest.py`에 고장 표본을 하나 더합니다 (시험이 빠진 것을 잡아 줌).
4. `--selftest`와 `pytest tests/infra`를 돌려 정상 0 · 경계 0 · 탐지 100 %를 확인합니다.
5. 바뀐 필드·규칙을 대조표 "명세 변경 반영" 절에 적습니다.
6. 명세가 blt 묶음을 제외로 표기하면 (D-14) `spec_excluded_groups()`가 그 표기를 읽어 `excluded = true`로 남깁니다. 표기 형식은 "## 6. … (blt) … 제외" 제목이나 "제외 묶음: blt" 줄입니다. 다른 형식이면 정규식을 고칩니다.

## 8. 한계

**검증기 자체의 한계**

- 문장 연결은 "그 문장을 맡은 규칙이 있다"까지 기계로 확인합니다. 규칙이 문장 뜻을 정확히 옮겼는지는 사람이 봐야 합니다 (팀장 검사 §8.2 무작위 10행).
- 조건부 필드 가운데 `frame.t_cam_ns` · `frame.cam_seq` ("카메라가 주면")는 파일 안 한 행이라도 값이 있으면 모든 행 필수로 읽었습니다. `meta.camera_temp_c`는 실측이면 센서 유무를 몰라 선택으로 둡니다.
- X-MET-07 ("같은 세션에서 layer_idx가 크면 더 큼")은 같은 세션의 **같은 시편·반복** 안에서만 봅니다. 한 세션에 높이가 다른 시편이 여럿이면 문자 그대로는 맞지 않기 때문입니다.
- 스캔 구간 규칙 (X-POS-03 ~ 07)은 호스트 시각으로 바꾼 scan_start ~ scan_end 사이 행만 봅니다. `pos.clock = mcu`인데 `clock_offset_ns`가 빈 행은 구간 판정에서 빠집니다 (그 행은 REQ가 따로 잡음).
- `frames.npz` 대안 저장은 키가 있는지만 봅니다. npz 안 배열의 지문·크기·비트 검사는 하지 않습니다.
- 기준 촬영 폴더 이름과 `ref.ref_id`가 같은지는 명세에 없는 규칙이라 검사하지 않습니다.
- 디스크 폴더를 읽을 때 Windows 백신 검사로 새 파일 열기가 느립니다 (파일 하나 약 50 ms). 자체 시험은 정상 표본만 디스크에 한 번 쓰고 나머지는 메모리에서 돌립니다.
- blt 묶음은 꺼져 있어 `bltouch/` 폴더의 CSV를 읽지 않습니다. `--enable-group blt`로 켜면 자동 규칙만 돕니다 (조건부 REQ 조건과 교차 규칙은 만들지 않음, D-14).

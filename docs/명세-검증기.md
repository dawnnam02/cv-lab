## 1. 실행법

Git Bash에서 저장소 뿌리 기준입니다. 설치 명령은 없습니다 (`requirements.txt`의 7개가 이미 깔려 있어야 함).

```bash
# 환경 점검 (판이 다르면 종료 코드 1)
PYTHONIOENCODING=utf-8 python scripts/check_env.py

# 명세 → 스키마·규칙표 다시 뽑기
PYTHONIOENCODING=utf-8 PYTHONPATH=src python scripts/extract_spec_schema.py
PYTHONIOENCODING=utf-8 PYTHONPATH=src python scripts/extract_spec_schema.py --check          # 저장본과 같은지만

# 캠페인 검사
PYTHONIOENCODING=utf-8 PYTHONPATH=src python scripts/validate_dataset.py data/raw/VC-2026-11-20-A --report out.json
# 저장소 밖 데이터 (명세 8절: 물리 뿌리는 설정). 저장소 뿌리는 기본으로 이 cv-lab
PYTHONIOENCODING=utf-8 PYTHONPATH=src python scripts/validate_dataset.py C:/cvlab_data/raw/VC-2026-11-20-A
# 기본 켬 규칙 끄기 (D-21 채택: W-REF-11 = 판정 거부 X4, W-MET-56 = X7만 끌 수 있음). 둘 다 WARN이라 종료 코드는 그대로
PYTHONIOENCODING=utf-8 PYTHONPATH=src python scripts/validate_dataset.py data/raw/VC-… --disable-rule W-MET-56
# 저장소 뿌리를 직접 줌 (meta.gcode_file · meta.slicer_profile_file 검사, FILE-17 · 18)
PYTHONIOENCODING=utf-8 PYTHONPATH=src python scripts/validate_dataset.py /어딘가/VC-… --repo-root /다른/cv-lab
# 설정 파일을 바꿔 줌 (기본 config/default.yaml, T6 절만 읽고 검사)
PYTHONIOENCODING=utf-8 PYTHONPATH=src python scripts/validate_dataset.py data/raw/VC-… --config my_default.yaml

# 자체 시험 (정상·경계·고장 표본)
PYTHONIOENCODING=utf-8 PYTHONPATH=src python scripts/validate_dataset.py --selftest --report "$TEMP/t6_selftest.json"

# 시험
PYTHONIOENCODING=utf-8 PYTHONPATH=src python -m pytest tests/infra -q -p no:cacheprovider
```

| 종료 코드 | 뜻 |
|---|---|
| 0 | ERROR 0건 (WARN은 있어도 됨) |
| 1 | ERROR 1건 이상 (자체 시험이면 하나라도 놓침) |
| 2 | 사용법 오류 (모르는 `--enable-rule` ID, 끌 수 없는 `--disable-rule` ID 포함), 폴더 없음, 스키마 파일 없음, 명세 지문이 `SOURCE.txt`와 다름, `_truth` 경로, 설정 오류 (아래) |

**설정 검사 (팀장검증 5차 S-4).** CLI는 T6 소유 `config/default.yaml` 하나만 읽습니다 (다른 담당 yaml이 바뀌어도 멈추지 않게). 대신 그 파일의 T6 절 (run · grid · paths · validate)을 `cvlab.config.load_owned()`로 `load_config()`와 같은 SCHEMA · 모르는 키 · 빠진 키 · 자료형 검사를 해서, 오타 키 (`enable_rule`) · 목록이 아닌 값 (`disable_rules: W-MET-56`)은 조용히 넘기지 않고 종료 코드 2와 "절 'validate'에 모르는 키 ['enable_rule']" 같은 문구를 냅니다.

**기본 켬 규칙 끄기 (D-21).** X4 · X7은 D-21 채택 (10-27)으로 기본 켬입니다. 끌 수 있는 규칙은 이 둘뿐이고 (`validate.SWITCHABLE_OFF`), 다른 ID를 끄려 하면 종료 코드 2입니다. 어디에 적어도 꺼집니다 (합침).

| 스위치 | 쓰는 법 |
|---|---|
| 명령줄 | `--disable-rule W-MET-56` (여러 번 쓸 수 있음) |
| 설정 | `config/default.yaml`의 `validate.disable_rules: [W-MET-56]` (지금 `[]`) |
| Python | `Validator(fields, rules, file_cols, disabled_rules={"W-MET-56"})` |

`--enable-rule` · `validate.enable_rules` · `enabled_rules`는 상태 '비활성' 규칙을 켜는 스위치로 남겨 두었습니다 (v1.0에서 비활성 규칙 0개).

**저장소 뿌리 (팀장검증 5차 S-5).** `meta.gcode_file`·`meta.slicer_profile_file`은 저장소 뿌리 기준 경로입니다 (명세 0.1절). 명세 0.1 · 8절은 "데이터 뿌리가 어디든 cv-lab 저장소 기준"이므로, CLI는 `--repo-root`가 없으면 **이 스크립트가 있는 cv-lab 저장소**를 씁니다. 데이터가 `C:\cvlab_data\raw\<id>`처럼 저장소 밖에 있어도 FILE-17 · 18을 건너뛰지 않습니다. 쓴 뿌리는 화면 (`저장소 뿌리: … (기본 …)`)과 보고 JSON (`repo_root` · `repo_root_source`)에 적습니다. 옛 추정 (`<뿌리>/data/raw/<id>`이면 그 뿌리, 아니면 건너뜀)은 뺐습니다. Python으로 `Validator`를 직접 부를 때 `repo_root` · `repo_exists`를 안 주면 지금처럼 건너뜁니다 (자체 시험은 `selftest.REPO_FILES`로 정함).

보고 JSON의 `findings` 행마다 `rule_id · severity · file · row · field · value · message`가 있습니다. `row`는 CSV 줄 번호 (머리글 = 1), 파일 전체 규칙이면 `null`입니다. 최상위에는 `campaign · repo_root · repo_root_source · disabled_rules · summary`도 있습니다.

Python에서 쓸 때:

```python
from cvlab.io.schema_files import load
from cvlab.io.validate import DirFS, Validator
fields, rules, file_cols = load()
v = Validator(fields, rules, file_cols, repo_root=".")
findings = v.run(DirFS("data/raw/VC-2026-11-20-A"), "VC-2026-11-20-A")
# 참값 객체 (T3가 이미 읽은 사전, 파일은 열지 않음). 같은 v의 run() 뒤면 캠페인 사실 v.truth_ctx
# (step_gauge 유무 · 층 · 쓴 GB- ID · blind · 스캔 ID · 주입 요인 · v1.2 재료 조각 (재료, 색) 쌍)와 대조함. ctx=…로 직접 줄 수도 있음
truth_findings = v.check_truth(truth_obj)
```

## 2. 스키마 추출 규칙

`scripts/extract_spec_schema.py` → `cvlab.io.spec_schema.extract()`. 손으로 옮기지 않습니다.

| 열 | 뽑는 법 |
|---|---|
| `field` … `rule_text` | 명세에서 `` ^\| `(frame\|pos\|cal\|ref\|meta\|blt\|rep\|truth)\.[a-z0-9_]+` \| `` 인 행. `' \| '`로 나눈 칸이 7개가 아니면 추출 실패 (종료 코드 2). 13절 "제외한 필드" 표는 첫 칸이 `blt (D-14)`라 필드로 읽지 않음 |
| `regex` | "정규식 `…`" (+ "또는 `…`")의 식. 여러 개면 `\|\|`로 잇고 하나라도 맞으면 통과. 조건이 붙은 정규식 ("…면 정규식")은 뽑지 않음 |
| `enum` · `enum_pending` | "값 ∈ {…}" 목록 (쉼표로 나눔), 문장 전체가 "값 = v"면 그 하나. 뒤에 `[대기: T14]`가 붙으면 `enum_pending = true` → 그 ENUM 규칙은 WARN. T1 2차에서 표시가 모두 풀려 지금은 0개 |
| `min` · `min_op` · `max` · `max_op` | 문장 단위로 "a ≤ x ≤ b", "0 < x", "x ≥ c", "abs(x) ≤ c", "= v". 끝값이 다른 필드면 비우고 CROSS 규칙이 맡음. "…면 x ≥ 100"처럼 조건이 붙은 범위는 뽑지 않음. 유니코드 빼기 (−)는 `-`로, `2^63`은 정수로. v1.1: `ref.gauge_height_mm` 범위 문장이 나뉘어 ("0 ≤ x ≤ 60. x = 0은 …") v1.0의 "범위 뒤 쉼표 조건" 특례를 지움 (특례 없이 0 ≤ x ≤ 60을 뽑음, 뒤 조건은 X-REF-23) |
| `file` | 묶음별 파일 (§0.2). cal·rep는 파일이 둘이라 `;`로 이음. `cal_results.csv` 열 목록은 명세 3절 문장에서 뽑음 |
| `excluded` · `excluded_reason` | 명세가 묶음을 제외로 표기하면 true, 사유는 명세 절 (`명세 6절 제외 표기 (D-14)`). 표기 형식은 절 제목 `## 6. … (blt) — 제외 (D-14)` 또는 본문 줄 첫머리 `제외 묶음: blt.` 둘 다. 명령줄 `--exclude-groups`는 명세 표기가 없을 때만 씀 (기본 blt). 지금 blt 필드 행이 없어 모든 행이 false |
| `order` | 필드표 순서 (CSV 열 순서 검사에 씀) |

- `config/spec/SOURCE.txt`에 명세 SHA-256, 뽑은 시각, 묶음별 필드 수, 제외 묶음과 사유, 규칙 수 (상태별)를 적습니다. fields·rules CSV는 두 번 뽑아도 같은 바이트입니다 (시험 `test_extract_is_deterministic`).
- 명세 지문이 `SOURCE.txt`와 다르면 `test_infra_schema_sync`가 실패하고 검증기는 종료 코드 2로 멈춥니다.
- 고정 파일 이름 (명세 8절): `meta.json` · `frames_index.csv` · `position_log.csv` · `cal_manifest.csv` · `cal_results.csv` · `ref_index.csv` · `design.csv` · `design_executed.csv` (+ 참값 쪽 `truth.json`). `probe_points.csv` · `probe_accuracy.csv`는 T1 2차에서 빠짐.

**문장 연결 방식.** 검사 대상 필드의 "검증 규칙" 칸을 문장 (`. ` 기준)으로 나누고, 문장마다 맡은 규칙을 찾습니다 (`rules.classify_sentences`). 자동 규칙이 맡는 문장은 모양으로 알아보고, 나머지는 손 규칙의 `covers` (필드 + 문장 일부)로 잇습니다. 검사할 내용이 없는 설명문 43개 (v1.0에서 4개 더함: LM-T14-2 불확도 안내 · step_gauge 기본값 · ref.calibration_id 선택 kind · ref.layer_idx 선택 kind. v1.1에서 2개 더함: spec_version "새로 쓰는 데이터는 1.1" (v1.2에서 "1.2"로 바꿈) · blind "블라인드는 스캔 있는 캠페인으로만")는 사유와 함께 `rules.NOTES`에 둡니다 (예: "SV08 = corexy" 기종별 값 예시, "판을 모르면 unknown" 작성 안내, "판정에는 in_process만" 판정 단계 몫). 연결되지 않은 문장이 하나라도 있으면 추출 스크립트가 종료 코드 1, 시험 `test_no_unclassified_sentence`가 실패합니다. `covers`의 글자가 명세 문장에 실제로 있는지도 시험합니다 (`test_every_cover_snippet_is_used`).

## 7. 명세가 바뀌면 할 일

1. `PYTHONPATH=src python scripts/extract_spec_schema.py`로 다시 뽑습니다. 미분류 문장이 있으면 목록이 나오고 종료 코드 1입니다.
2. 미분류 문장마다 `src/cvlab/io/rules.py`에 손 규칙 (`_h(...)`, `covers`에 필드:문장 일부), 보류 (사유 필수), 설명문 (`NOTES`) 중 하나를 더합니다. 새 조건부 필드는 `CONDITIONS`와 `validate.COND_FUNCS`에 같은 키로 넣습니다.
3. 새 손 규칙은 `validate.py`에 `emit("ID", …)`로 구현하고 (ID를 글자 그대로 써야 시험이 찾음), `selftest.py`에 고장 표본을 하나 더합니다.
4. 사용자 결정을 기다리는 규칙은 상태 `비활성`, 사유에 결정 번호와 켜는 법을 적습니다. 결정으로 기본 켬이 됐지만 끌 수 있어야 하는 규칙은 `validate.SWITCHABLE_OFF`에 넣고 `selftest.switch_tests()`에 표본을 넣습니다 (D-21 X4 · X7이 이 경우).
5. `--selftest`와 `pytest tests/infra`를 돌려 정상 0 · 경계 0 · 탐지 100 %를 확인합니다.
6. 바뀐 필드·규칙을 대조표에 적습니다.
7. 동결 (v1.0) 뒤 명세를 고칠 점은 명세를 직접 고치지 않고 대조표 · §8에 "다음 판 후보"로 적습니다 (명세 머리 판 올림 규칙). 판이 오르면 `meta.spec_version` 허용 값이 바뀌므로 정상 표본 (`selftest._meta`)의 판도 맞춥니다.
8. (끝남) D-21은 10-27 채택: v1.0 재동기화에서 W-REF-11 · W-MET-56을 `구현` · 기본 켬으로 바꿈. 심각도는 WARN 유지 (§4 끝 이유).
9. WARN 규칙이 "나오면 안 되는 경우"도 있으면 (두 단 비처럼 음성 · 경계 표본) `selftest.ratio_tests()` 꼴로 넣어 경고 시험에서 함께 셉니다.
10. 교차 규칙의 정상 쪽 끝값 (C2 교정 Z + 0.02처럼 "여기까지는 통과")은 `selftest.c2_tests()` 꼴로 넣어 경계 위반 수에 셉니다 (ERROR · WARN 모두 0).
11. 판이 오르며 허용 값에 들어간 고장 표본 (v1.2의 spec_version 1.2)은 다음 판 값 (1.3)으로 바꿉니다.

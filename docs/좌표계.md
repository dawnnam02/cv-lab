# 좌표계 {I}{C}{S}{M}{G}

> 작업: T7a (세부청사진_T7a_레이저선추출 §6.7 – 6.9) · 요소 청사진: C4 · 기준: `docs/하드웨어-데이터-명세.md` 0.4절 (884daac) · 코드: `src/cvlab/triangulation/frames.py` · `geometry.py`
> 교정값은 모두 인자로 받습니다 (기본값 없음). 실제 교정은 T8 (D1 – D4)입니다. 이 문서의 변환은 합성 기하로만 시험했으며 C4 · C5 (교정 · 종단 정확도)의 증거가 아닙니다.

## 0. 요약

- 좌표계 다섯 개 ({I} 이미지, {C} 카메라, {S} 센서, {M} 측정, {G} G코드)를 명세 0.4절 그대로 씁니다. 모두 오른손 좌표계이고 {S} · {M} · {G}의 z는 위 +입니다.
- 변환 이름은 `T_<to>_<from>` (`T_G_M` = {M}의 점을 {G}로). 코드 `Tf`가 이름이 안 맞는 곱과 거울 · 배율 행렬을 거부합니다.
- 영상 점 → {G} 점: `p_G = T_G_M · (T_S_C · (광선 ∩ 레이저 평면) + s · a_S)`, a_S = R_S_C · `scan_axis_C`. 함수 `image_to_G(uv_full, scan_s_mm, calib)`.
- 고리마다 필요한 교정값: K · dist (D1), 레이저 평면 · T_S_C (D2), 스캔 축 (D3), T_G_M (D4 + 위치 로그). 빠지면 오류.
- 명세 0.4 높이 식의 Z_n · d_s는 이 사슬로 나오고, 메시 항 [m(x_n, y_n) − m(x_p, y_p)]은 T9 (H3)에서 더합니다.

## 1. 다섯 좌표계

명세 0.4절 표와 같습니다 (줄마다 대조). 마지막 열은 이 문서 · 코드가 더한 설명입니다.

| 표기 | 이름 | 원점 · 축 (명세 0.4) | 단위 | 만드는 곳 | 코드 · 설명 |
|---|---|---|---|---|---|
| {I} | 이미지 | 왼쪽 위 화소 중심, u 오른쪽 (열), v 아래 (행) | px | 카메라 | `img[v, u]`. 추출 결과 v는 ROI 행 → `roi_to_full` (+ `frame.roi_y0_px`), u는 + `frame.roi_x0_px` |
| {C} | 카메라 | 렌즈 광학 중심, OpenCV 규칙 (x 영상 오른쪽, y 영상 아래, z 보는 방향) | mm | D1 | `pixel_to_ray`가 {C} 단위 광선을 냄 |
| {S} | 센서 | 레이저 평면 위 기준점, x 레이저 선 방향, z 위 | mm | D2 | y = z × x (오른손). C4: y = 레이저 평면의 법선 (스캔 방향). {S}의 x–z 평면 = 레이저 평면 |
| {M} | 측정 | 스캔 시작 위치의 {S} 원점, y 스캔 진행 방향 + | mm | D3 | p_M = p_S + s · a_S. 축 방향은 {S}와 같음 (§8 ③) |
| {G} | G코드 | 프린터 원점 (G28 뒤), 베드 면 Z = 0, 노즐 끝 기준 | mm | 프린터 | 비교 · 판정 좌표 (C4 §4). 스캔 진행 = 프린터 Y (M54, `meta.scan_axis` 기본 +Y), 레이저 선 ≈ 프린터 X |
| 기계 | 기계 좌표 | 스텝 계수를 mm로 바꾼 값, 메시 보정이 들어간 실제 축 위치 | mm | 펌웨어 | 기계 Z = {G} Z + `pos.mesh_dz_mm` (명세 0.4). 이 사슬에는 들어가지 않음 |

- 레이저 선 방향 = {S} x ≈ 프린터 X, 스캔 방향 = {M} y = 프린터 Y (명세 0.4 "스캔 진행 방향은 프린터 Y축"). 프린터마다 실제 +X · +Y 방향은 §7 L자 시편으로 확인합니다 (C4 §5).

## 2. 이름 규칙 (T_to_from)

```
p_G = T_G_M · p_M              ("G ← M")
T_G_S = T_G_M @ T_M_S          가운데 글자 M이 맞닿아 지워짐
T_M_G = T_G_M.inv()
```

| 규칙 | 코드 (`Tf`) |
|---|---|
| 이름 | `Tf(to, frm, R, t).name` = `"T_<to>_<frm>"`. 좌표계 이름에 밑줄 금지 (이름을 다시 나눌 수 있게) |
| 곱 | `A @ B`는 `A.frm == B.to`일 때만, 결과 `T_<A.to>_<B.frm>`. 아니면 ValueError |
| 회전 | det(R) = +1 ± 1e-6, RᵀR = I ± 1e-6이 아니면 ValueError (거울 · 배율 · 비틀림 거부) |
| 역 | `.inv()` → `T_<frm>_<to>`, R → Rᵀ, t → −Rᵀt |
| 적용 | `.apply(P)`: P [N, 3] 또는 [3], 같은 모양으로 돌려줌. p′ = R p + t |
| 저장 | 4 × 4 (`.M`, `Tf.from_matrix`). 명세 `truth.t_g_m`과 같은 꼴 (마지막 행 [0, 0, 0, 1]) |

시험 (합성): 왕복 오차 최대 4.3e-14 mm (< 1e-9), 잘못된 곱 · 거울 · 배율 거부 100 % (`tests/triangulation/test_tri_frames.py`, 검증 명령 ④).

## 3. 영상 → {G} 변환 사슬 (고리별 교정값과 출처)

```
(u, v)_I ──pixel_to_ray(K, dist)──▶ 광선 r_C ──intersect_plane(laser_plane_C)──▶ p_C
p_C ──T_S_C──▶ p_S ──(+ s · a_S)──▶ p_M ──T_G_M──▶ p_G
```

| 고리 | 함수 | 교정값 (인자) | 단위 | 정하는 단계 | 명세 필드 (뜻) |
|---|---|---|---|---|---|
| {I} → {C} 광선 | `pixel_to_ray(uv, K, dist)` | `K` 3 × 3, `dist` (k1, k2, p1, p2[, k3]) | px · 무차원 | D1 카메라 내부 | `truth.cam_k` · `truth.cam_dist` (OpenCV 순서) |
| 광선 ∩ 레이저 평면 | `intersect_plane(rays, plane)` | `laser_plane_C` [nx, ny, nz, d], n·p + d = 0, \|n\| = 1 | d mm | D2 레이저 평면 | `truth.laser_plane` ({C}) |
| {C} → {S} | `T_S_C.apply` | `T_S_C` (`Tf`, 이름 T_S_C) | mm | D2 (평면 + 선 방향 + 기준점) | 직접 필드 없음 (평면과 선 방향에서 만듦) |
| {S} → {M} | p_M = p_S + s · a_S | `scan_axis_C` ({C} 단위 벡터), 프레임마다 s | mm | D3 스캔 축 · 위치 로그 | `truth.scan_axis` ({C}). s는 아래 |
| {M} → {G} | `T_G_M.apply` | `T_G_M` (`Tf`, 이름 T_G_M) | mm | D4 센서 ↔ G코드 · 위치 로그 | `truth.t_g_m` · `truth.nozzle_sensor_offset_mm` ({G}) |

- **스캔 위치 s** (mm, 스캔 시작에서 진행 방향으로 잰 거리, ≥ 0). 트리거 경로 ⓐ (`frame.trigger_mode` = hw): s = `meta.scan_speed_mm_s` × `frame.trig_pulse_idx` × `meta.trigger_period_s` (명세 1절, 펌웨어 문서 §9 "y = y0 + v · k · T"). 시작 Y `meta.scan_y0_mm`와 부호 (`meta.scan_axis`)는 T_G_M의 이동 · 회전에 들어갑니다. 그 밖 경로 (gate · sw · free)는 `pos.y_mm`을 프레임 시각으로 보간 (T9).
- **왜곡 식** (OpenCV 순서, `distort_points`): r² = x² + y², x_d = x(1 + k1 r² + k2 r⁴ + k3 r⁶) + 2p1 xy + p2(r² + 2x²), y_d = y(…) + p1(r² + 2y²) + 2p2 xy. 풀기 (`undistort_points`)는 뉴턴 반복 최대 50회, 허용 1e-12. 수렴하지 않거나 왜곡 함수가 접히는 가지 (1 + k1 r² + … ≤ 0 또는 야코비안 ≤ 0)면 경고 + NaN. 명세 `truth.cam_dist`가 허용하는 8 · 12 · 14개 계수 중 k4 이후 항은 0일 때만 받습니다 (아니면 ValueError, [확인 필요]: D1이 5개 모델을 쓰는지).
- **교정값에 기본값이 없습니다.** `calib`에 `CALIB_KEYS` = (K, dist, laser_plane_C, T_S_C, scan_axis_C, T_G_M) 중 하나라도 없으면 ValueError, `T_S_C` · `T_G_M`은 이름이 맞는 `Tf`여야 합니다.
- 시험 (합성 기하, 검증 명령 ④ · `test_tri_geometry.py`): 카메라 광축과 레이저 평면 30°, {S} 원점 렌즈 앞 50 mm, 평면 [0, −0.866, 0.5, −25] (명세 부록 A 예시와 같은 꼴) → {G} 점 최대 오차 8.8e-11 mm (< 1e-6). 왜곡 식 차 0, 풀기 왕복 9.7e-13 (정규 좌표). 이 기하 값은 시험용 가정입니다.

## 4. 높이 식 (명세 0.4)과의 관계

명세 0.4: `h(p) = Z_n + d_s(p) + [m(x_n, y_n) − m(x_p, y_p)]` ({G} Z, 베드 면 = 0).

| 기호 | 이 사슬에서 | 맡는 곳 |
|---|---|---|
| d_s(p) | 노즐 끝 기준 센서 거리. {S}에서 잰 점의 z에 D4 노즐-센서 오프셋 (`truth.nozzle_sensor_offset_mm`의 z, {G})을 더한 값 | T_S_C (D2) · T_G_M의 오프셋 부분 (D4) |
| Z_n | 스캔 중 노즐 끝의 {G} Z (`pos.z_mm`) | T_G_M의 z 이동 (스캔마다 위치 로그로 채움) |
| 메시 항 | `pos.mesh_dz_mm` (노즐 XY) − 메시 표 (측정점 XY) | **T9 (H3)에서 더함. 이 작업은 넣지 않음** |

- 그래서 `image_to_G`의 z = Z_n + d_s(p)이고, h(p) = 그 z + [m(x_n, y_n) − m(x_p, y_p)]입니다 (T_G_M을 스캔마다 노즐 위치 + D4 오프셋으로 만들 때).
- 0점 (베드 기준 스캔 `ref.kind` = bed_bare, `meta.zero_ref_method`)과 층별 0점 이어 가기는 T9 몫입니다.
- 높이는 측정 당시 값입니다 (D-06). 열 상태 환산은 하지 않습니다.

## 5. 격자 약속 (A[iy, ix], 칸 중심)

| 항목 | 약속 (C4 §2 · §4) |
|---|---|
| 배열 | 높이맵 · 마스크 2차원 배열은 `A[iy, ix]` (행 = Y, 열 = X). numpy `meshgrid` 기본 (`indexing="xy"`)과 같음 |
| 좌표 | x = x0 + ix · res, y = y0 + iy · res. **칸 중심** 좌표 (`truth.heightmap_origin_mm` = 첫 칸 중심) |
| 간격 | res = 0.02 mm 기본 (`truth.heightmap_step_mm`, C4) |
| 그림 | `imshow(..., origin="lower", extent=[x0 − res/2, x1 + res/2, y0 − res/2, y1 + res/2])`. 기본값 (0행 위)은 위아래가 뒤집혀 보임 |
| 영상과 혼동 금지 | 영상은 `img[v, u]`이고 v는 아래 + ({I}). 높이맵의 iy는 {G} Y + 방향. 영상 배열을 높이맵처럼 그리지 않음 |

## 6. 단위 · 각도 · 부호

| 항목 | 약속 |
|---|---|
| 길이 | mm (내부 · 저장). µm은 보고 표에서만 (`_um` 접미사). 화소는 px |
| 각도 | 내부 계산 rad, 설정 · 보고 deg (`_deg` · `_rad` 접미사, 명세 0.3). `np.radians`로 바꿈 |
| 높이 | {S} · {M} · {G} 모두 z 위 +. OpenCV {C}의 y (아래 +)를 높이로 쓰지 않음 |
| 오차 부호 | Δ = 실측 − 정답 (+ = 재료 과다), 명세 0.4 |
| 회전 | 오른손, det = +1. 거울 행렬로 축 뒤집힘을 "고치지" 않음 (데이터를 손으로 뒤집지 않음) |
| 영상 행 | v는 아래 +. 높이가 오르면 v가 어느 쪽으로 가는지는 배치에 따름 (명세 부록 A 예시 기하에서는 위로 = v 감소) [계산: 시험 기하에서 확인] |

## 7. 실측 때 축 검사 (L자 시편)

C4 §5 · §6 그대로 (T7a는 문서만, 실행은 실측 단계):

1. 프린터에서 `G28` 뒤 `G1 X10`, `G1 Y10`으로 +X · +Y가 실제 어느 쪽인지 눈으로 확인하고 사진에 표시.
2. 비대칭 L자 시편 (긴 팔 40 mm +X, 짧은 팔 25 mm +Y, 폭 5 mm, 높이 2 mm)을 출력 · 스캔.
3. 측정 높이맵 (`A[iy, ix]`)에서 높이 > 1 mm 마스크를 만들고 G코드 기준 마스크와 8가지 (회전 0/90/180/270° × 좌우 거울) IoU 비교. 최적이 "회전 0°"이고 IoU ≥ 0.9이면 통과.
4. 실패하면 어느 축이 뒤집혔는지 찾아 **T_S_C 또는 T_G_M 정의를 고친 뒤** 다시 검사 (데이터를 손으로 뒤집지 않음). 대칭 시편 (정사각형 · 원)은 쓰지 않음.

## 8. 명세 · 요소 청사진과 다른 점

명세와 요소 청사진은 고치지 않고 여기에 적어 팀장에게 넘깁니다.

| 번호 | 다른 점 | 이 작업의 처리 |
|---|---|---|
| ① | C4 §2는 {S} y = "레이저 평면의 법선 (스캔 방향)"을 적고, 명세 0.4는 {S}의 x · z만 적음 | 명세와 모순은 아님. y = z × x로 정해지며, 이 문서 §1에 C4 설명을 덧붙임 |
| ② | C4 §2는 {G} 원점을 "G28 후 기계 좌표"라고 적지만, 명세 0.4는 {G}와 기계 좌표를 나누고 기계 Z = {G} Z + 메시로 둠 | 명세를 따름. {G}는 메시가 빠진 G코드 좌표 |
| ③ | 스캔 축이 레이저 평면에 정확히 수직이 아니면 "{S} y = 스캔 방향"이 근사가 됨 | {M}은 {S}를 s · a_S만큼 옮긴 것 (축 방향은 {S}와 같음)으로 정의하고, a_S는 D3 `scan_axis_C`에서 계산 (y축이라고 가정하지 않음). 명세 {M} "y 스캔 진행 방향"은 수직일 때의 근사로 읽음 [확인 필요: 팀장] |
| ④ | C4 §3 산출물 경로 (`src/cvlab/frames.py`, `docs/hardware/C4_frames.md`)와 다름 | 세부청사진 T7a 경로 (`src/cvlab/triangulation/frames.py`, 이 문서) |
| ⑤ | C4 §6 `Tf`는 det만 검사 | RᵀR = I도 검사 (비틀림 · 배율 행렬 거부), 좌표계 이름에 밑줄 금지 |
| ⑥ | 명세 `truth.cam_dist` 길이 ∈ {4, 5, 8, 12, 14} | 4 · 5개만 계산, k4 이후 항은 0일 때만 받음 |
| ⑦ | 명세 1절 `frame.file`은 "조건부" (`meta.raw_saved` = false면 빈 칸)인데 세부청사진 §6.9는 필수 열로 둠 | 열은 필수로 검사하고, 값이 빈 행을 `load_frame`하면 ValueError |

## 9. 한계

- 변환 사슬은 합성 기하로만 시험했습니다 (교정값 없음). 실제 교정 (D1 – D4)과 C4 · C5 판정은 T8 · T3 평가용 세트 몫입니다.
- 렌즈는 핀홀 + OpenCV 5계수 왜곡만 다룹니다. 샤임플러그 (센서 기울임) · 텔레센트릭 모델은 없습니다 [확인 필요: B2 배치가 샤임플러그를 쓰는지].
- 레이저 평면은 완전한 평면으로 봅니다 (선 휨 · 굽음 없음).
- {M} → {G}는 스캔 동안 고정인 강체 변환입니다. 스캔 중 Z 흔들림 · 요 회전 (C1 · C7)은 넣지 않았습니다 (T9에서 위치 로그로 보정할지 결정).
- 메시 항 · 0점 이어 가기 · 열 상태는 이 작업 밖입니다 (§4).
- 명세가 바뀌는 중입니다 (884daac 기준, 팀장 검토 전). 명세 0.4가 바뀌면 §1 표를 다시 대조합니다.

## 0. 목적과 공통 규칙

하드웨어가 있었다면 나왔을 데이터를 필드 단위로 정합니다. 시뮬레이터(T3)는 이 명세대로 데이터를 만들고, 처리 코드(T7 이후)는 이 명세대로 읽습니다. 실제 장비 데이터도 같은 명세로 들어오면 코드를 고치지 않고 돌립니다.

### 0.1 쓰는 법 (가상·실측 공통)

| 규칙 | 내용 |
|---|---|
| 한 명세 | 가상과 실측이 **같은 파일·같은 필드**를 씁니다. 다른 점은 `meta.source` 값 하나와 12절의 조건부 필드뿐입니다 |
| 필드 이름 | `묶음.필드`. 파일 안에서는 묶음 접두어를 뺀 이름이 열 이름(CSV) 또는 키(JSON)입니다. 예: `meta.nozzle_temp_c` → `meta.json`의 키 `nozzle_temp_c` |
| 필수/선택 | `필수` = 항상 값이 있어야 함. `선택` = 없으면 빈 칸(CSV) 또는 `null`(JSON). `조건부` = 검증 규칙 칸에 적은 조건일 때 필수, 아니면 빈 칸 |
| 예시 값 | 필드표와 부록 B의 예시 값은 **형식을 보이려고 만든 값**입니다. 측정값이 아닙니다. 하드웨어 사양 값만 M54·M03 출처를 따릅니다 |
| 검증 규칙 | T6 명세 검증기가 그대로 코드로 옮길 수 있게 범위·허용 값·정규식·다른 필드와의 관계로 씁니다 |
| 원본 불변 | `data/raw/`는 한 번 쓴 뒤 고치지 않습니다 (F3 규칙). 폴더가 이미 있으면 쓰기 오류를 냅니다. 고칠 일이 생기면 새 스캔 ID로 다시 만듭니다 |
| **참값 분리** | 가상 데이터의 참값은 `data/_truth/<campaign_id>/`에만 둡니다. `data/raw/` 안에는 참값이 한 글자도 없어야 합니다 (청사진 §5.2). `truth.` 필드가 `data/raw/` 아래 파일에 나오면 검증 실패입니다 |
| 숫자 근거 | `[출처]` M54·M03 등 문서, `[계산]` 식을 함께, `[추정]` 이유를 함께, `[미상]` 모름 |
| **측정 시점 (D-04 확정, 2026-10-27 사용자 결정)** | 기본은 **층마다 측정**입니다. 층 출력이 끝날 때마다 노즐 장착 라인 레이저로 그 층 윗면을 스캔합니다. 스캔 1회 = 층 1개. 출력이 다 끝난 뒤 베드 위 최종 스캔은 **선택 묶음**입니다 (`meta.timing` = post, 폴더 `post/`) |
| 층 단위 필수 필드 | 모든 스캔에 층 번호·층 Z·그 층의 G코드 줄 범위·층 출력 종료 시각·종료부터 스캔 시작까지 경과 시간·노즐/베드 온도·스캔 때문에 노즐이 멈춘 시간이 **필수**입니다 (5절 `meta.layer_idx` `meta.layer_z_mm` `meta.gcode_line_start` `meta.gcode_line_end` `meta.layer_end_t_ns` `meta.wait_after_layer_s` `meta.nozzle_temp_c` `meta.bed_temp_c` `meta.pause_added_s`). frame·pos 행에도 층 번호가 들어갑니다 |
| 스캔 폴더 | `<스캔 폴더>` = `data/raw/<campaign_id>/sessions/<session_id>/<specimen_id>_r<반복 2자리>/<layer_dir>/` (세션 / 시편 / 층). `<layer_dir>`는 층별이면 `L` + 층 번호 3자리 (예: `L004`), 출력 후 최종 스캔이면 `post`. 세션 = 출력 작업 1회 (8절) |

- 옛 F3의 `room_temp_C`처럼 대문자 단위는 쓰지 않습니다 (부록 C).

### 0.4 좌표계·시계

**좌표계** (C4 정의를 그대로 씀, 모두 오른손 좌표계, 높이는 z 위쪽 +):

| 표기 | 이름 | 원점·축 | 이 명세에서 쓰는 곳 |
|---|---|---|---|
| {I} | 이미지 | 왼쪽 위 화소 중심, u 오른쪽(열), v 아래(행), px | `frame.roi_*_px` (화소 색인. 공간 mm 필드가 아님) |
| {C} | 카메라 | 렌즈 광학 중심, OpenCV 규칙 | `truth.cam_k`, `truth.laser_plane` |
| {S} | 센서 | 레이저 평면 위 기준점, x 레이저 선 방향, z 위 | `truth.nozzle_sensor_offset_mm` |
| {M} | 측정 | 스캔 시작 위치의 {S} 원점, y 스캔 진행 방향 + | `truth.scan_axis`, `truth.t_g_m` |
| {G} | G코드 | 프린터 원점 (G28 뒤), 베드 면 Z = 0, 노즐 끝 기준 | `pos.x_mm`, `blt.x_mm`, `cal.feature_x_mm` 등 대부분 |
| 기계 | 기계 좌표 | 스텝 계수를 mm로 바꾼 값. 베드 메시 보정이 들어간 실제 축 위치 | `pos.source = steps` 행, `pos.mesh_dz_mm` |

- 기계 Z와 {G} Z의 관계: `기계 Z = {G} Z + pos.mesh_dz_mm`.
- 위치가 아닌 길이·두께·간격 필드(예: `meta.layer_h_mm`, `cal.gauge_nominal_mm`)는 뜻 칸에 "크기 값, 좌표계 무관"으로 적습니다. 방향이 있는 길이는 "{G} Z 방향 길이"처럼 적습니다.
- 노즐 장착 방식(M54)이라 센서는 노즐과 함께 움직입니다. 스캔 진행 방향은 프린터 Y축입니다 (M54: "Y 20 µm, 2.4 mm/s").

**시계** (시각 필드는 모두 ns 정수, 어느 시계인지 뜻 칸에 적음):

| 시계 | 뜻 | 필드 |
|---|---|---|
| 카메라 시계 | 카메라 내부 카운터. 카메라가 줄 때만 있음 [미상: OV9281 USB 모듈이 주는지] | `frame.t_cam_ns` |
| 호스트 단조 시계 | 수집 PC의 단조 시계 (예: `time.monotonic_ns`). 벽시계 조정에 흔들리지 않음. **모든 시각을 비교하는 기준 시계** | `frame.t_host_ns`, `pos.t_ns` (clock = host), `ref.t_start_ns`, `blt.t_ns` |
| 프린터 MCU 시계 | 프린터 제어 보드 시계 (예: Klipper MCU 시각) | `pos.t_ns` (clock = mcu) |
| 벽시계 (ISO 8601) | 사람이 읽는 날짜·시각, 시간대 `+09:00` 붙임 (F3 결정) | `meta.datetime`, `cal.created`, `cal.valid_from`, `cal.valid_until` |

- 호스트 시계로 옮기는 식: `t_host = t_mcu + pos.clock_offset_ns`.
- 한 스캔의 `meta.datetime`은 그 스캔 첫 프레임의 `frame.t_host_ns`와 같은 순간을 벽시계로 적은 값입니다.

### 0.5 결측·인코딩·CSV 규칙

| 항목 | 규칙 |
|---|---|
| 문자 인코딩 | UTF-8, BOM 없음 (F3: 한글 메모 허용) |
| CSV | 쉼표 구분, 첫 줄 머리글, 소수점 `.`, 줄 끝 `\n`. 머리글은 묶음 접두어를 뺀 필드 이름. 열 순서는 필드표 순서 |
| JSON | 들여쓰기 2칸, `ensure_ascii=False`. 키는 묶음 접두어를 뺀 필드 이름 |
| 결측 | CSV 빈 칸, JSON `null`. `NaN`·`-1`·`0`으로 결측을 나타내지 않음 |
| 참거짓 | 소문자 `true`, `false` |
| 정수 시각 | 64비트 정수. 지수 표기(1e9) 금지 |
| 실수 | 유효 숫자를 잃지 않게 씀. 길이 mm는 소수 4자리 이상 (0.1 µm) |
| 목록 값 (JSON) | JSON 배열. CSV 칸에는 목록을 넣지 않음 |
| 경로 | 해당 묶음 폴더 기준 상대 경로, 구분자 `/` |
| 층 번호 | 0부터 (C2 규칙) |
| 덮어쓰기 | 금지. 같은 이름 파일이 있으면 오류 |

## 1. 원시 프레임 (frame)

**목적.** 카메라가 낸 영상 그대로를 비트 손실 없이 남기고, 프레임마다 시각·노출·ROI·레이저 상태를 적습니다. 처리 코드가 프레임과 위치를 시각으로 맞출 수 있게 카메라 시각과 PC 수신 시각을 둘 다 둡니다.

**파일 형식과 위치.**

| 파일 | 형식 | 규칙 |
|---|---|---|
| `<스캔 폴더>/frames/<frame_idx 6자리>.png` | 무손실 PNG, 1채널. 8비트 영상은 8비트 그릇, 10·12비트 영상은 16비트 그릇에 하위 비트 정렬 | 기본안 |
| `<스캔 폴더>/frames.npz` | numpy 묶음, 키 `f000000` … (uint8 또는 uint16) | 대안 (파일 수가 너무 많을 때) |
| `<스캔 폴더>/frames_index.csv` | CSV, 프레임 1장 = 1행 | 필수 |

- JPEG 저장 금지 (F3: 손실 압축이 중심 위치를 바꿈). 카메라가 MJPG만 낼 수 있으면 받은 그대로 PNG로 풀어 저장하고 `frame.lossy = true`로 표시합니다.
- 레이저 끈 프레임(배경)도 같은 색인에 넣고 `frame.laser_on = false`로 표시합니다.

**필드표.**

| 필드 | 뜻 | 단위 | 자료형 | 필수/선택 | 예시 | 검증 규칙 |
|---|---|---|---|---|---|---|
| `frame.scan_id` | 이 프레임이 속한 스캔 ID | - | str | 필수 | S01_r01_L004 | 정규식 `^S\d{2}_r\d{2}(_L\d{3})?$`. 파일 안 모든 행이 같고 `meta.scan_id`와 같음 |
| `frame.layer_idx` | 이 프레임을 찍은 층 번호, 0부터 (출력 후 최종 스캔이면 마지막 층 번호) | - | int | 필수 | 4 | 0 ≤ x. 파일 안 모든 행이 같고 `meta.layer_idx`와 같음 |
| `frame.frame_idx` | 스캔 안 프레임 번호, 0부터 | - | int | 필수 | 0 | 0 ≤ x. 첫 행 0, 행마다 1씩 증가, 중복 없음 |
| `frame.file` | 영상 파일 위치, 스캔 폴더 기준 상대 경로 | - | str | 조건부 | frames/000000.png | `meta.raw_saved` = true면 필수, false면 빈 칸. 정규식 `^frames/\d{6}\.png$` 또는 `^frames\.npz#f\d{6}$`. 숫자 6자리 = `frame.frame_idx`. 파일이 실제로 있음 |
| `frame.sha256` | 영상 파일 SHA-256 지문 (누락·손상 탐지, T2 MF-DAT-06) | - | str | 조건부 | a1b2…(64자) | `frame.file`이 있으면 필수. 정규식 `^[0-9a-f]{64}$`. 다시 계산한 값과 같음 |
| `frame.t_cam_ns` | 노출 시작 시각, 카메라 시계 | ns | int64 | 조건부 | 1000000 | 카메라가 시각을 주면 필수, 아니면 빈 칸. 있으면 행마다 증가 |
| `frame.t_host_ns` | PC가 프레임을 다 받은 시각, 호스트 단조 시계 | ns | int64 | 필수 | 4990008333 | 0 < x. 이전 행보다 큼 |
| `frame.cam_seq` | 카메라가 매긴 프레임 일련번호 (빠짐 탐지용) | - | int | 조건부 | 1201 | 카메라가 주면 필수. 이전 행보다 큼 |
| `frame.exposure_us` | 이 프레임의 실제 노출 시간 (카메라에서 읽은 값) | µs | float | 필수 | 800.0 | 0 < x ≤ 1e6 ÷ `meta.fps`. 스캔 안에서 모두 같음 (자동 노출 끔) |
| `frame.gain_db` | 아날로그 게인 (카메라에서 읽은 값) | dB | float | 필수 | 0.0 | 0 ≤ x. 스캔 안에서 모두 같음 (자동 게인 끔) |
| `frame.bit_depth` | 화소 값의 유효 비트 수 | - | int | 필수 | 10 | 값 ∈ {8, 10, 12, 16}. 8비트 그릇 PNG면 8. 화소 최댓값 ≤ 2^x − 1 |
| `frame.pixel_format` | 카메라가 실제로 보낸 형식 | - | str | 필수 | GRAY10 | 값 ∈ {GRAY8, GRAY10, GRAY12, GRAY16, MJPG, YUYV}. 스캔 안에서 같음 |
| `frame.lossy` | 손실 압축을 거친 영상인지 | - | bool | 필수 | false | `frame.pixel_format` = MJPG이면 true, 그 밖은 false. true면 처리 코드가 경고를 남김 |
| `frame.roi_x0_px` | ROI 왼쪽 위 열, {I} | px | int | 필수 | 0 | 0 ≤ x. x + `frame.roi_w_px` ≤ `meta.cam_res_w_px` |

## 3. 교정 원자료 (cal)

**목적.** D1–D5 교정에 쓰는 원자료 목록과 교정 결과 파일의 위치·유효 기간을 남깁니다. 어떤 스캔이 어떤 교정으로 처리되었는지 `meta.calibration_id`로 이어집니다.

**파일 형식과 위치.**

```
calibration/<cal_id>/
  cal_manifest.csv      ← 원자료 1건 = 1행 (아래 필드표)
  d1/  view_000.png …   ← D1 카메라 내부: ChArUco 자세별 사진
  d2/  pose_00_off.png, pose_00_on.png …   ← D2 레이저 평면: 평판 높이별 켬·끔 쌍
  d3/  move_00.png …    ← D3 스캔 축: 명령 이동별 사진
  d4/  plate_scan/ …    ← D4 노즐-센서: 교정 판 원기둥 스캔, 노즐 접촉 기록
  d5/  gauge_0p20/ …    ← D5 검증: 필러게이지 단차 스캔
```

- 결과 파일(YAML)은 `config/calibration/<cal_id>/`에 둡니다 (D1–D5 청사진). `cal.result_file`이 그 경로를 가리킵니다.

## 5. 메타데이터 (meta)

**목적.** 스캔 1회(= 층 1개)의 모든 조건을 한 파일에 적습니다. 센서 사양, 프린터·펌웨어·슬라이서, 재료, 온도, 층 정보, 측정 시점, 대기·정지 시간, 교정 ID, 소프트웨어 버전, 가상이면 시뮬레이터 버전·시드·주입한 실패 요인까지 담습니다.

**파일 형식과 위치.** `<스캔 폴더>/meta.json` (스캔마다 1개, JSON 객체 하나). 키는 접두어를 뺀 필드 이름입니다. 센서 사양 값의 출처는 M54 "대표 구성"과 "사양" 표입니다.

## 6. BLTouch 검증 (blt)

**목적.** 가상(나중엔 실제) BLTouch로 단차 면과 필러게이지 위를 짚은 점을 남깁니다. 레이저 단차와 비교하는 교차검증(C7, Bland–Altman) 원자료입니다.

**파일 형식과 위치.**

| 파일 | 행 단위 |
|---|---|
| `bltouch/<session_id>/probe_points.csv` | 프로빙 1회 (점 하나의 샘플 하나) = 1행 |
| `bltouch/<session_id>/probe_accuracy.csv` | PROBE_ACCURACY 실행 1회 = 1행 |

- `<session_id>`는 BLTouch 세션 ID (`BLT-…`)입니다. 출력 세션 폴더 안 `sessions/<session_id>/bltouch/<blt 세션 ID>/`에 둡니다 (8절).
- 면 폭 조건: 핀 지름 약 2 mm (M03, 추정) → 단차 면 폭 ≥ 3 mm (비교-선정 §000). 점은 면 가장자리에서 핀 반경 1 mm 이상 떨어져야 합니다.
- 두 파일은 열 구성이 다릅니다. probe_points.csv는 아래 표에서 `blt.accuracy_*`를 뺀 열, probe_accuracy.csv는 `blt.session_id`·`blt.point_id`·`blt.x_mm`·`blt.y_mm`·`blt.samples`·`blt.speed_mm_s`·`blt.accuracy_range_um`·`blt.accuracy_std_um`·`blt.t_ns` 열입니다.

## 8. 폴더 구조와 이름 규칙

**원칙.**
- 세션(출력 1회) / 시편 / 층 순서로 나눕니다 (D-04 층별 측정 확정). 스캔 1회 = 층 1개 = 폴더 1개.
- `data/raw/`는 처리 코드가 읽는 곳입니다. **참값은 한 글자도 없습니다.** 참값은 `data/_truth/`에만 둡니다 (0.1 참값 분리).
- `data/raw/`는 쓰기 한 번 뒤 읽기 전용입니다. 폴더가 이미 있으면 쓰기를 거부합니다 (F3).

## 9. 용량 계산

**입력** (모두 M54): 1280 × 800 화소, 최대 120 fps, 스캔 간격 20 µm, 스캔 길이 40 mm, 스캔 속도 2.4 mm/s, 심도 약 8 mm, 배율 0.19, 화소 3 µm, 삼각 각 30°.

**기본 계산 [계산].**

| 항목 | 식 | 값 |
|---|---|---|
| 스캔 1회(층 1개) 프레임 수 | 40 mm ÷ 0.02 mm | 2,000장 (배경 프레임 약 10장 더하면 +0.5 %) |
| 스캔 1회 시간 | 40 mm ÷ 2.4 mm/s | 16.7 s |
| 화소당 높이 | 3 µm ÷ (0.19 × sin 30°) | 31.6 µm |
| 높이 방향 ROI 행 수 | 8 mm ÷ 31.6 µm = 253 → 16의 배수로 올림 | 256행 |
| USB 2.0 비교 기준 | 480 Mbit/s ÷ 8 | 60 MB/s (이론값, 실효는 더 낮음) |

**프레임·스캔·전송률 [계산]** (1 MB = 10^6 B, 1 GB = 10^9 B):

| 경우 | 프레임 1장 | 층 1회 스캔 (2,000장) | 120 fps 전송률 | USB 2.0 (60 MB/s) |
|---|---|---|---|---|
| 전체 8비트 | 1280 × 800 × 1 = 1,024,000 B | 2.05 GB | 122.9 MB/s | 넘음 (2.0배) |
| 전체 16비트 그릇 | 1280 × 800 × 2 = 2,048,000 B | 4.10 GB | 245.8 MB/s | 넘음 (4.1배) |
| ROI 1280 × 256, 8비트 | 1280 × 256 × 1 = 327,680 B | 0.66 GB | 39.3 MB/s | 안 넘음 (66 %) |
| ROI 1280 × 256, 16비트 그릇 | 655,360 B | 1.31 GB | 78.6 MB/s | 넘음 (1.3배) |
| ROI 1280 × 256, 10비트 꽉 채움 (1.25 B/화소) | 409,600 B | 0.82 GB | 49.2 MB/s | 이론상 안 넘음 (82 %). 카메라가 이 형식을 내는지 [미상] |

- 전체 8비트를 USB 2.0으로 받을 때 최대 속도: 60 ÷ 1.024 = **58.6 fps** [계산]. 그러면 20 µm 간격 스캔 속도는 58.6 × 0.02 = 1.17 mm/s, 스캔 1회 40 ÷ 1.17 = 34.1 s가 됩니다 [계산].
- 결론: 120 fps를 지키려면 **ROI 1280 × 256, 8비트**가 USB 2.0에서 유일하게 여유 있는 경우입니다. 카메라가 이 ROI를 못 하면 MJPG(손실)로 떨어질 수 있으므로 `frame.pixel_format`·`frame.lossy`로 표시합니다.
- 이 값은 무압축 크기(상한)입니다. PNG 압축률은 [미상]입니다 (F3: 레이저 영상은 대부분 어두워 압축이 잘 될 것으로 봄). 가상 캠페인 첫 세트에서 실제 크기를 재서 이 표 옆에 적습니다.

**층별 데이터량 (층 수 × 스캔당 용량) [계산].** 층 높이 0.2 mm 기준.

| 시편 층 수 (높이) | ROI 8비트 (0.66 GB/층) | 전체 8비트 (2.05 GB/층) | 전체 16비트 (4.10 GB/층) | 스캔 시간 합 (16.7 s/층) |
|---|---|---|---|---|
| 10층 (2 mm) | 6.55 GB | 20.5 GB | 41.0 GB | 2.8 분 |
| 20층 (4 mm) | 13.1 GB | 41.0 GB | 81.9 GB | 5.6 분 |
| 100층 (20 mm) | 65.5 GB | 204.8 GB | 409.6 GB | 27.8 분 (M54 "약 28분"과 일치) |

- 식: 시편 용량 = 층 수 × 2,000장 × 프레임 1장 크기. 예: 100 × 2,000 × 327,680 B = 65.5 GB.
- 스캔 시간 합은 순수 스캔만입니다. 노즐 들어 올림·이동·대기를 더한 실제 정지 시간은 `meta.pause_added_s`의 합으로 잽니다.
- 그 밖의 파일 [추정: 한 행 약 120자]: frames_index.csv 2,000행 ≈ 0.24 MB/층, position_log.csv는 펌웨어 보고 주기에 따라 다름 [미상]. 영상에 비하면 무시할 수준입니다.
- 정지 반복 기준 100장 (전체 16비트): 100 × 2,048,000 B = 204.8 MB/세션 [계산].

| 온도 | 시뮬레이터 열 모델 출력 | 센서 측정 |
| 측정자 (`meta.operator`) | sim, sim_A 등 | 사람 이름 |
| 교정 결과 | 가상 원자료로 계산, 참값과 비교 가능 | 실측 원자료로 계산, 참값 없음 (D5 검증만) |

| specimen_id | `meta.specimen_id` | 같음 |
| repeat | `meta.repeat` | 같음 |
| datetime | `meta.datetime` | 시간대 `+09:00` 필수 (F3 §4 결정 반영) |
| operator | `meta.operator` | 가상이면 sim |
| gcode_file | `meta.gcode_file` | 같음 |
| gcode_sha256 | `meta.gcode_sha256` | 64자 16진수 정규식 추가 |
| calibration_id | `meta.calibration_id` | 유효 기간 검사 추가 (`cal.valid_from`, `cal.valid_until`) |
| room_temp_C | `meta.room_temp_c` | 단위 접미사 소문자 |
| bed_temp_C | `meta.bed_temp_c` | 단위 접미사 소문자. 층별 측정이라 스캔 시작 때 값 |
| exposure_us | `meta.exposure_set_us` (설정) + `frame.exposure_us` (프레임별 실제) | 설정과 실제를 나눔 |
| gain_db | `meta.gain_set_db` (설정) + `frame.gain_db` (프레임별 실제) | 설정과 실제를 나눔 |

| scan_speed_mm_s | `meta.scan_speed_mm_s` | 같음 |
| notes | `meta.notes` | 빈 문자열 대신 "-" |
